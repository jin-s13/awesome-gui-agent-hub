Research Lines

Real-world GUI and OS task/dataset design

Introduces shared desktop, browser, dynamic short-video, and video-guided environments/tasks so agent capabilities can be compared on realistic settings rather than synthetic single-step screens.

Open edge: Coverage across interface types, long-horizon multi-app workflows, observation-control dynamics, and human-level cost-accuracy remains incomplete.
Fine-grained metric and diagnostic/stress-test design

Probes sub-goal completion, Pass@1 vs sub-goal gaps, cost-accuracy, observation behavior, and calibrated uncertainty/conformal regions beyond aggregate scores.

Open edge: Whether these proxy metrics align with downstream user decisions and whether uncertainty/diagnostic rankings transfer across model tiers and interfaces without re-evaluation.
Scaffold and training-based agent improvement

Raises agent performance through multimodal skill libraries, evidence-driven harness optimization, verifiable RL task synthesis, and weak supervision from unannotated screenshots.

Open edge: Stability across implementations and compute budgets, benchmark-specific overfitting, and how much gains transfer outside the evaluated benchmarks.
Video-guided and dynamic-screen observation/keyframe methods

Addresses dynamic content changes between actions by formalizing observation control and task-aware keyframe extraction for video-guided GUI tasks.

Open edge: Evidence is limited to short-video or VideoQA/GUI settings; broader dynamic interfaces and multi-step agentic trajectories require more validation.

Shared Direction

  • Recent work treats aggregate success as insufficient and adds sub-goal, cost-accuracy, observation, or uncertainty diagnostics.
  • Real-world tasks and dynamic interface settings expose a gap between current agent behavior and human-level control.
  • Substantial gains can come from scaffolds, skills, harness changes, or training data rather than only replacing backbone models, but reported gains need transfer evidence.
  • Several benchmark artifacts provide datasets/environments and evaluation protocols, yet missing limitation details and cross-setting validation remain verification gaps.

Key Differences

  • Evaluation target differs: single-step executable GUI grounding versus multi-step desktop workflows versus dynamic living-screen or video-guided tasks.
  • Improvement signal differs: multimodal visual skill artifacts, executable harness edits, verifiable RL task synthesis, and weak supervision from unannotated screenshots represent different assumptions about data and supervision.
  • Interaction/deployment setting differs: real macOS desktop, simulated browser short-video platforms, OSWorld/ScienceBoard/WindowsAgentArena-style environments, and video-guided GUI tasks are not interchangeable.
  • Metric emphasis differs: task success/checkpoint scoring, cost-accuracy, uncertainty ranking/conformal coverage, and video QA/agentic benchmark gains optimize different evaluation targets.

Open Questions

  • Do fine-grained benchmark metrics predict the downstream decisions users care about when controllability and observation cost matter?
  • How stable are benchmark rankings and agent improvements across platforms, interfaces, model tiers, and repeated runs?
  • Can scaffold/training gains be separated from benchmark-specific tuning under different implementations and compute budgets?
  • How should dynamic-screen and long-horizon GUI benchmarks cover observation control without overfitting to one platform such as short-video?
  • What missing limitation and artifact evidence would be needed to audit reproducibility across the broader benchmark corpus?

Research Lines

GUI benchmark and evaluation design

characterizes GUI grounding and computer-use capabilities with fine-grained scoring across desktop, dynamic, drag, and video-guided settings

Open edge: coverage is constrained by platform-specific task suites and short or single-step episodes; cross-interface and long-horizon generalization is not established
GUI action prediction via supervision, RL, and self-improvement

reduces reliance on human annotations and improves frozen or trainable models through unannotated screenshots, verifiable task synthesis, online RL, or execution-harness evolution

Open edge: gains are not yet isolated from backbone models, harness choices, task priors, or framework components; several limitations are unreported
Reliability and observation-aware grounding

quantifies grounding confidence, builds conformal click regions, and exposes missing observation control in dynamic interfaces

Open edge: existing evidence mostly covers single-step grounding; cross-model uncertainty transfer is weak and calibration degrades under interface or distribution shift

Shared Direction

  • Frontier VLMs still show non-human reliability gaps such as sub-goal failure, over- and under-observation, and weak cross-model uncertainty transfer.
  • Fine-grained evaluation beyond Pass@1 is needed because similarly successful agents differ on subgoals, information efficiency, or confidence quality.
  • Self-improvement, weakly supervised training, and RL scaling can improve open-source computer-use agents without solely relying on large human-annotated datasets.
  • Performance attribution is fragile: one study found a skill library, not framework design, drove the strongest configuration, pointing to system-level confounds.

Key Differences

  • Evaluation targets and interfaces differ: desktop GUI+CLI, dynamic short-video, drag interactions, video-guided tasks, and single-step GUI grounding produce incomparable capability estimates.
  • Improvement strategy differs: one line optimizes a frozen execution harness, another uses online RL with synthesized tasks, and another learns visual grounding from unannotated screenshots, implying different data and model-access assumptions.
  • Reliability assessment differs: one line targets post-hoc uncertainty ranking and conformal click regions, another targets observation cost, and another targets fine-grained task completion, without a shared multi-step protocol.

Open Questions

  • Which evaluation dimensions transfer across platforms, interfaces, and multi-step trajectories rather than remaining specific to a test suite?
  • How much of each reported gain comes from the proposed method versus backbone model, task synthesis, harness, or interface assumptions when limitations are not reported?
  • Can uncertainty scoring and conformal calibration remain valid across open and closed VLM families and under realistic GUI deployment shifts?
  • What observation-control or memory mechanism would reduce over- and under-observation in dynamic interfaces such as short-video platforms?
  • Can drag, video-guided, and desktop GUI benchmarks be unified into a shared action-grounding evaluation without sacrificing their specific validity?

theory

Formal analysis, task abstractions, interaction theory, or reliability/safety framing for GUI agents

58 Methodology quality 100 Recency 39 Reproducibility 40 Topical relevance

Literature review synthesis

Research Lines

Benchmark-driven task abstraction and capability annotation

Defines observable GUI agent capabilities through real-world multi-application task suites and fine-grained or cost-aware metrics.

Open edge: Whether task sampling transfers to deployment distributions and dynamic interfaces; formal relation between subgoal metrics and task success is missing.
Multimodal knowledge and reusable skill libraries

Encodes application workflows as retrievable multimodal artifacts to reduce exploratory interaction and improve UI identification.

Open edge: Whether visual skill artifacts generalize across application versions or interfaces, and how they depend on model-specific perception errors.
Evidence-driven harness evolution and self-improvement

Diagnoses recurrent failure patterns from repeated runs and optimizes execution scaffolding while keeping backbone models frozen.

Open edge: Transfer evidence is limited to tested benchmarks, and there is no formal guarantee of safe behavior after harness edits.
Scalable training with verifiable or weak supervision

Reduces annotation and compute burdens by synthesizing verifiable tasks or using unannotated screenshots for grounding and reinforcement learning.

Open edge: Direct validation that learned policies remain reliable on unseen workflows and do not overfit to narrow verifiable reward checks.

Shared Direction

  • GUI agent evaluation is shifting from single-application success rates to real-world, multi-application tasks with fine-grained or cost-aware scoring.
  • Visual grounding and interface perception are central bottlenecks; retaining visual information or learning grounding from screenshots improves performance.
  • Data and task synthesis, weak supervision, and verifiable reward are becoming major routes for improving GUI agents.
  • Reliability is operationalized through uncertainty quantification, failure-pattern diagnosis, or spatial safety regions rather than formal safety properties.
  • Frozen models can gain substantial performance from external scaffolds such as skill libraries or optimized execution harnesses.

Key Differences

  • Evaluation target differs: single-step grounding versus multi-step interactive workflows versus specific interaction primitives such as dragging.
  • Improvement locus differs: modifying frozen-model skills or harnesses versus updating model parameters through reinforcement learning or weak supervision.
  • Interface assumptions differ: static and deterministic desktop tasks versus dynamic continuously changing interfaces, leading to different failure attribution.
  • Supervision signal differs: human-annotated or generated verifiable tasks versus unannotated screenshots versus executable environment checks.
  • Reliability formulation differs: post-hoc uncertainty ranking versus conformal spatial safety versus evidence-driven failure-pattern diagnosis.

Open Questions

  • How do fine-grained multi-checkpoint scores relate to deployed task success when platforms and interface dynamics shift?
  • Can observation-control failures in dynamic interfaces be formalized and improved across interaction modalities?
  • Does uncertainty ranking transfer remain stable for multi-step agent trajectories and under cross-interface distribution shift?
  • Do skill-library and harness optimizations generalize across application versions without relying on platform-specific assumptions?
  • What guarantees connect verifiable training tasks or harness edits to safe behavior on unseen GUI workflows?

system

Runnable GUI agent systems, frameworks, sandboxes, tool-use platforms, or orchestration layers

58 Methodology quality 100 Recency 40 Reproducibility 41 Topical relevance

Literature review synthesis

Research Lines

End-to-end agent training and orchestration stacks

Trains agents that use complex inference harnesses or native GUI/code action spaces in executable environments, via RL or hybrid supervision.

Open edge: Error recovery remains weak after RL; harness design affects trainability; independent cross-team and cross-infrastructure reproduction is not yet established.
Efficient action policies and serving

Reduces inference latency or parameter count for GUI action selection through latent-space scoring or block-wise diffusion generation.

Open edge: Efficiency can trade off against accuracy and generalization; evidence is sparse outside AndroidControl and selected GUI benchmarks; limitations are partly unstated.
Weakly supervised and data-efficient learning

Builds GUI agents from large-scale unannotated screenshots to reduce expensive human annotation.

Open edge: Generalization beyond small calibration data and comparisons across broader supervision budgets are not fully evidenced.
Reusable multimodal skills and artifacts

Provides hierarchical multimodal skill knowledge that preserves visual figures for UI element identification and workflow verification.

Open edge: Coverage beyond reported benchmarks and independent reuse across applications remain uncertain.

Shared Direction

  • GUI and computer-use control is increasingly treated as a learnable multimodal policy rather than a fixed prompt-and-tool scaffold.
  • Training signal quality, action representation, and evaluation environment selection materially affect agent success.
  • Visual grounding signals, whether from screenshots or preserved figures, improve UI element identification and task execution.
  • Benchmarks such as OSWorld-Verified, AndroidControl, WebVoyager, and OSExpert-Eval are common but not yet sufficient for cross-platform claims.

Key Differences

  • Supervision strategy ranges from weakly supervised unannotated screenshots to verifiable hybrid supervision with online RL.
  • Action generation differs: latent candidate scoring, block-wise diffusion, autoregressive VLM output, and unified GUI/code actions are all proposed.
  • Evaluation targets differ: overall task success, recovery consistency, preference personalization, or latency-accuracy efficiency.
  • Deployment settings differ: mobile, web, desktop Linux, and Windows agents face different state, action, and rollback constraints.
  • Some systems train the actual deployment harness while others train standalone policies, making harness-specific trainability a contested boundary.

Open Questions

  • How can efficient latent or diffusion-based GUI policies close accuracy gaps beyond narrow benchmarks like AndroidControl?
  • What training signals or reset-like mechanisms can teach reliable error recovery when current agents fail to exploit latent recovery capabilities?
  • What supervision mix best balances annotation cost, verifiability, and generalization across web, mobile, desktop, and Windows settings?
  • How do multimodal skill artifacts and behavior memory logs generalize beyond small task distributions, and how can evidence selection be improved?
  • Which harness and infrastructure design choices are necessary for reproducible agent training across teams and deployments?

60 Methodology quality 100 Recency 39 Reproducibility 42 Topical relevance

Literature review synthesis

Research Lines

Cross-application desktop and operating-system task benchmarking

Evaluates GUI agents on real macOS desktop tasks that require GUI and CLI actions across multiple applications, with fine-grained sub-goal scoring.

Open edge: Whether macOS-specific pass@1 and sub-goal metrics transfer to other operating systems, dynamic interfaces, and long-horizon professional workflows.
Multimodal skill and reusable workflow memory for computer-use agents

Improves computer-use agent success and speed by retrieving hierarchical multimodal application skills or compiling successful runs into state-machine replays.

Open edge: Robustness of stored skills and compiled programs to interface updates, new task variants, and cross-application transfer.
Dynamic and specialized GUI interaction benchmarking

Covers short-video living-screen tasks, video-guided GUI tasks, and drag-based interactions that are underrepresented in click-focused benchmarks; measures task accuracy and observation efficiency.

Open edge: Generalization beyond the selected platforms and interaction types, and why current models lack observation control in dynamic content.
Efficient or generative GUI-agent model training

Trains a block-wise diffusion vision-language agent for GUI grounding and navigation, providing an alternative to autoregressive generation.

Open edge: Whether diffusion-based training matches or exceeds strong frontier models on broader mobile, desktop, and web tasks under deployment latency constraints.

Shared Direction

  • Real-world GUI evaluation requires executable, application-grounded environments rather than static screenshots alone.
  • Frontier agents still fail on observation control, fine-grained grounding, or specialized interactions, so task success alone is insufficient as an evaluation target.
  • Reusable structured knowledge such as multimodal skills, compiled state-machine programs, or generated trajectories improves task success, speed, or downstream fine-tuning.
  • Evaluation is expanding to cover interaction types and efficiency dimensions beyond click-only actions, including drag, video-guided tasks, GUI+CLI, and dynamic content.

Key Differences

  • Evaluation targets differ: one-shot Pass@1, cost-accuracy and observation efficiency, sub-goal completion, and repeated-task speed are not interchangeable.
  • Environment scope differs: fixed macOS desktop applications, simulated short-video platforms, reconstructed wild websites, and video-guided interactions emphasize different failure modes.
  • Remedy strategy differs: retrieval-augmented multimodal skill memory, run compilation to state machines, generative model training, and environment/trajectory construction address different bottlenecks.
  • Interaction modality assumptions differ: some evaluations rely on static display assumptions, while others adopt dynamic, drag-based, video-guided, or combined GUI/CLI workflows.

Open Questions

  • Do gains on platform-specific benchmarks transfer to live professional workflows across operating systems and application versions?
  • How should observation control be learned or evaluated for dynamic interfaces where content changes between actions?
  • How robust are stored skills and compiled programs when application UI changes, tasks vary, or agents meet unseen workflows?
  • Do reconstructed wild-web environments preserve sufficient fidelity for agents fine-tuned on them to remain safe and effective on live sites?
  • What evidence gaps remain from missing public code, datasets, model checkpoints, or limitation reports for several methods in the packet?

Shared Direction

Key Differences

  • Evaluation targets differ: some work targets single-step grounding or uncertainty, others long-horizon mobile/desktop task completion, fraud recall, or inference latency.
