Screenshots or Tools? Eliciting Tool Use and Managing Multimodal Context in Hybrid GUI-MCP Computer-Use Agents

arXiv 2026 56.6 method

TLDR

Hybrid GUI-MCP agents vary in tool use; reasoning models improve while non-reasoning degrade, and context compression reduces cost with retraining gains.

Reasoning

The paper provides strong empirical evidence (5 runs, beyond 2 SE) on the OSWorld-MCP benchmark, identifying an adoption gap and showing that tool bonuses improve adoption but not accuracy. A limitation is that the bottleneck lies in tool-call semantics, and training partially addresses competence.

Deep Analysis

Innovations

  • Discovery that identical MCP tools can improve a reasoning model while degrading a non-reasoning model, attributed to tool-decision behavior.
  • Introduction and quantification of the 'adoption gap' – the shortfall between tool-available tasks and actual tool calls by even reasoning models.
  • Use of multi-turn RL with a dense tool bonus to probe the action level, showing that behavior can be steered but competence does not follow.
  • A context compression method that drops redundant post-tool-call screenshots, halving image history, and retrains under the same observation rule to recover accuracy, reducing input tokens by about a third.

Methodology

The study uses the OSWorld-MCP benchmark (309 tasks) with a hybrid GUI-MCP agent harness. It compares reasoning and non-reasoning models under identical tool availability, applies multi-turn reinforcement learning with a tool-use bonus, and investigates a context compression technique that removes screenshots after tool calls, followed by retraining under that observation rule.

Key Results

Under the same harness, MCP tools improve a reasoning model by +4.0pp and degrade a non-reasoning model by -5.9pp (both significant beyond 2 SE). The reasoning model calls a tool on only 55/309 tasks (23.9% of reachable ones); a dense tool bonus raises adoption but does not improve held-out accuracy, while context compression with retraining reaches 37.8% accuracy vs 33.0% uncompressed at 53% input cost and closes the rich-lean gap to zero.

Limitations

  • Tool-use behavior is steerable but competence is not; the bottleneck lies in tool-call semantics, and held-out accuracy does not follow from increased adoption.
  • The adoption gap remains largely unaddressed, with only 23.9% of tool-reachable tasks called even by the reasoning model.
  • Context compression requires retraining under the same observation rule to remove the initial small accuracy cost, adding a training dependency.
  • Findings are demonstrated on a single benchmark (OSWorld-MCP) and two model types, limiting generalizability.
