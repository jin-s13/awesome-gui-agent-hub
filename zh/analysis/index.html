研究路线

基准任务与数据集设计

创建涵盖多应用、多交互类型（GUI+CLI、拖拽、视频引导）和动态环境的共享任务，使代理能力评估具备可比性。

尚未覆盖：任务分布是否覆盖所有真实部署场景，以及对动态界面演化的泛化能力仍有限。
指标与压力测试设计

在总体成功率之外，通过细粒度子目标评分、信息效率和不确定性量化，检验预测、可控性、鲁棒性和决策效用。

尚未覆盖：代理指标与用户真正关心决策之间的一致性未经证实，且这些指标在分布外场景下的鲁棒性不足。
可比基线与报告规范

通过公开的基准、代码和训练流水线使结果可审计，促进可复现性和方法比较。

尚未覆盖：基准结论在不同实现和算力预算下的稳定性，以及缺乏统一的报告惯例。

研究共性

  • 多模态视觉语言模型是所有场景下GUI代理的基础。
  • 评估必须超越简单任务成功率，引入细粒度进展、效率或不确定性维度。
  • 动态和多样化的交互（拖拽、视频、命令行）是静态点击式GUI的关键扩展方向。
  • 数据稀缺和标注成本推动了弱监督、合成任务生成和样本高效训练的方法。

关键差异

  • 交互界面：桌面操作系统环境 vs 短视频平台 vs 纯拖拽界面。
  • 评估重点：任务完成准确性 vs 信息效率（成本-准确性） vs 不确定性量化。
  • 监督信号：全标注示范 vs 利用未标注截图的弱监督 vs 可验证合成任务。
  • 部署环境：真实操作系统 vs 基于浏览器的模拟器。
  • 指标粒度：单步成功 vs 多步子目标完成。

开放问题

  • 当前基准任务分布在多大程度上能代表真实世界中GUI交互的全貌，包括移动端和企业软件？
  • 代理能否针对动态内容变化界面形成有效的观察控制策略，何种指标可衡量该能力？
  • 后验不确定性量化方法在跨模型系列和跨接口迁移时有多鲁棒，部署需要何种校准？
  • 细粒度基准得分与用户实际满意度或任务完成效用之间存在怎样的经验关系？
  • 基于合成数据或弱监督数据训练的代理能否泛化到训练分布之外的真实新颖应用和工作流？

theory

Formal analysis, task abstractions, interaction theory, or reliability/safety framing for GUI agents

63 方法质量 99 近期性 39 可复现性 49 主题相关性

文献综述归纳

研究路线

基准测试与评估框架

提供标准化、多样化的环境（桌面、动态信息流、拖拽交互）和指标（细粒度检查点、不确定性量化），衡量GUI代理的能力和局限性。

尚未覆盖：多数基准未覆盖安全关键场景；跨基准泛化性未知；UQ基准仅限于单步基础，且在分布偏移下性能下降。
技能与上下文增强

通过注入结构化多模态技能库或主动上下文管理，提升长时域或复杂任务性能，减少遗忘和UI元素误识别。

尚未覆盖：技能构建仍依赖人工或半自动流程，难以泛化到新应用；上下文管理策略缺乏在不同模型架构上的验证。
训练与数据效率

通过可验证任务合成与在线强化学习，或大规模无标注截图的弱监督，减少对昂贵人工标注的依赖，以有限标注数据达到竞争性能。

尚未覆盖：在线强化学习缺乏安全与稳定性保证；弱监督可能引入噪声，损害真实任务上的鲁棒性；缺乏对训练数据质量和分布的理论分析。
形式化与不确定性分析

对动态界面代理和后验UQ方法进行形式化，为可靠性提供理论视角，并系统比较UQ在不同模型和数据集间的迁移性。

尚未覆盖：形式化定义尚未与经验模型行为校准；UQ方法在分布偏移下失效，且未集成到代理的安全决策回路中。

研究共性

  • 多模态输入（视觉截图与文本）对GUI代理至关重要；任务通过率被广泛使用，但细粒度子目标指标能揭示隐藏的性能差异。
  • 当前模型在动态界面、长时域任务和拖拽交互上仍存在显著性能差距，与人类水平有较大距离。
  • 需要更多基准来覆盖超越简单点击的交互类型，包括拖拽、滚动和视频信息流观察。

关键差异

  • 评估理念：部分工作采用确定性基于规则的评分，另一些则采用任务准确性与信息效率的联合指标，以惩罚不必要的观察。
  • 性能提升路径：一条路线依赖外部技能库，另一条通过在线强化学习微调模型，第三条利用无标注数据的弱监督进行预训练。
  • 不确定性处理：开源权重模型表现出较强的模型内UQ迁移，但跨模型迁移很弱，表明UQ策略必须根据模型架构和访问级别定制。

开放问题

  • 如何将不确定性量化集成到动作选择中，以实现更安全的GUI代理？
  • 什么样的观察控制形式约束可以保证在动态、持续变化的界面中的鲁棒性能？
  • 如何使在线强化学习训练在真实计算机使用场景中安全且稳定地部署？
  • 如何在不依赖人工编写的情况下，自动构建技能库并在应用间迁移？

method

GUI agent models, planning, grounding, action prediction, training, or reasoning methods

61 方法质量 99 近期性 39 可复现性 49 主题相关性

文献综述归纳

研究路线

方法表示与目标设计

将GUI代理能力转化为可学习的表示、损失函数和训练配方，包括从未标注截图学习弱监督定位、为视频引导任务提取关键帧、拖拽动作表示以及用于长时程记忆的结构化上下文字段。

尚未覆盖：这些表示在跨平台和跨任务下的迁移性；当任务多样性增加时弱监督的极限；关键帧提取是否能泛化到视频问答之外。
规划与动作接口方法

将学习到的策略连接到决策时接口，如使用高效rollout分配（Frontier Sampling）的在线RL、作为第一类动作的主动上下文管理（ConAct）以及生成训练信号的可验证任务合成。

尚未覆盖：收益有多少来自模型本身而非规划器或上下文管理器；上下文管理策略在未见应用领域中的鲁棒性；在线RL在真实GUI环境中的安全性和探索成本。
方法证据与消融协议

通过针对性基准测试分离方法贡献与数据集、基线和实现因素，揭示观察控制失败模式、技能库与框架效应分解、拖拽交互缺口以及跨模型和数据集的后验不确定性量化迁移性。

尚未覆盖：跨模型层级和接口迁移时UQ排名的稳定性；非点击交互评估的完备性；基准特定发现是否在分布偏移下仍然成立。

研究共性

  • GUI代理主要基于视觉语言模型构建，并通过新引入的基准测试上的任务完成指标进行评估。
  • 普遍认识到当前代理缺乏关键能力：观察控制、长时程上下文管理以及对拖拽或动态界面的支持。
  • 通过利用未标注数据、合成任务生成或课程学习，追求最小化人工标注量来改善训练。
  • 评估必须超越Pass@1，包括细粒度子目标评分、成本-准确性权衡和不确定性质量。

关键差异

  • 监督信号：一些工作依赖海量未标注截图进行弱监督，另一些通过RL生成可验证的合成任务，还有一些使用完全标注的轨迹。
  • 评测目标：任务成功率（MacAgentBench）对成本-准确性（LivingScreen）对不确定性可靠性（Argus）对拖拽专用准确率（DragOn）。
  • 交互模态：基准测试覆盖范围从桌面GUI+CLI混合到移动长时程任务、动态短视频平台和仅拖拽交互。
  • 训练体制：离线监督微调（MemGUI）对在线RL加前沿采样（SCALECUA）对两阶段课程加RL校准（GUICrafter）。

开放问题

  • 弱监督或合成任务生成带来的收益能否迁移到训练分布之外的真实GUI任务？
  • 上下文管理和在线RL策略如何扩展到具有不可逆操作的安全关键应用？
  • 基准测试必须覆盖的最小交互类型集是什么，才能可靠预测真实世界代理性能？
  • 当内部状态不可访问时，不确定性量化排名在闭源模型层级间是否保持稳定，应如何指导代理设计？

system

Runnable GUI agent systems, frameworks, sandboxes, tool-use platforms, or orchestration layers

60 方法质量 99 近期性 39 可复现性 47 主题相关性

文献综述归纳

研究路线

可运行流水线与部署栈

将模型训练与推理整合为端到端工作流，支持在线强化学习、弱监督或大规模监督微调，用于GUI代理。

尚未覆盖：错误恢复在RL训练后仍薄弱；框架设计显著影响可训练性，跨环境泛化尚未保证。
实时与交互式服务

通过脚手架设计管理多轮截图历史和真实网站交互，满足低延迟和交互性需求。

尚未覆盖：离线基准无法捕捉异步时序、延迟和实时动态；速度、保真度与系统复杂度之间的权衡缺乏系统研究。
工件与可复现工程

通过多模态技能库、动作接地视觉记忆和步骤级诊断基准，使系统行为可检查、可复用。

尚未覆盖：多模态技能库的自动化构建、跨团队和基础设施的独立复现，以及记忆机制对动态环境的泛化。

研究共性

  • 视觉记忆对GUI代理至关重要，但朴素全图记忆可能引入视觉杂乱，恶化动作级错误。
  • 在真实网站或桌面上的在线强化学习能显著提升代理性能，但需要大规模部署基础设施。
  • 多模态信息（图像+文本）在UI元素识别和工作流状态验证中优于纯文本表示。
  • 安全加固是领域条件的：在浏览器提示注入上鲁棒的代理，在编码任务中可能对同类攻击仍然脆弱。

关键差异

  • 训练范式：使用真实环境的在线RL versus 基于未标注截图的离线弱监督 versus 使用脚手架回放的大规模监督微调。
  • 技能表示：分层多模态技能库（VISUALSKILL） versus 动作接地图像裁剪（AGMem） versus 无显式技能存储。
  • 评估目标：对GUI过渡的步骤级诊断理解（Desktop-Delta Bench） versus 在线基准上的端到端任务成功率。
  • 安全范围：仅针对浏览器的威胁模型 versus 揭示领域条件安全特性的跨领域比较。

开放问题

  • 离线诊断基准如何指导在线训练，以改善隐藏操作盲区等特定失败模式？
  • 技能库和视觉记忆在什么条件下能跨应用和操作系统泛化？
  • 为何某些框架明显更难学习，哪些设计选择决定了可训练性？
  • 如何在RL训练中显式地针对错误恢复进行优化，鉴于该能力在各框架中仍普遍薄弱？

application

Domain applications of GUI agents, such as office automation, mobile apps, web tasks, software operation, or professional tools

65 方法质量 99 近期性 38 可复现性 51 主题相关性

文献综述归纳

研究路线

领域特定GUI代理基准构建

评估GUI代理在真实应用场景（桌面、动态视频、拖拽、欺诈检测）中的细粒度能力，揭示观察控制差、良性召回低、多应用任务完成弱等不足。

尚未覆盖：基准间缺乏统一评估协议；增强方法仅在孤立基准上测试，跨基准泛化性未知；部分基准（如欺诈检测）移除了现实中的信誉信号，真实部署表现未经验证。
基于知识与记忆的代理能力增强

通过注入预定义多模态技能、将成功运行编译为可重放状态机、或增加历史感知与视觉基础的批评模型，提升代理成功率、执行效率或规划稳健性。

尚未覆盖：这些增强与特定环境或任务深度绑定，缺乏跨领域迁移证据；技能库的构建与更新成本、编译程序的泛化能力、批评模型的训练数据偏差等依然未被探索。

研究共性

  • GUI代理在真实应用中的表现仍远未达到人类水平，需要结合视觉信息、历史上下文和细粒度反馈来改进。
  • 评估指标应从简单的任务成功率扩展到子目标完成度、成本-准确性以及执行效率，以捕捉代理行为的细微差别。

关键差异

  • 关注点不同：有的聚焦交互原语（拖拽 vs. 点击 vs. 动态内容），有的聚焦任务类型（办公自动化 vs. 欺诈检测 vs. 视频引导任务）。
  • 改进策略不同：通过技能库进行离线知识注入，与基于成功运行进行在线学习（重放编译）或实时批评形成对比。
  • 评估环境不同：从真实macOS桌面、移动设备到基于浏览器的模拟器，影响了结果的真实性和可复现性。

开放问题

  • 技能库、重放编译和在线批评等增强方法能否跨不同基准和交互类型迁移？
  • 观察控制（何时停止观察、何时回退）能否通过元学习或强化学习优化，而非依赖硬编码启发式？
  • 多模态技能库的自动构建和跨应用泛化在缺乏大量人工编写的情况下是否可行？
  • 在欺诈检测等安全关键应用中，如何在不依赖当前基准中被人为移除的信誉捷径的情况下，提高良性召回率？

survey

Surveys, taxonomies, tutorials, position papers, or roadmap papers for GUI agents

57 方法质量 98 近期性 37 可复现性 47 主题相关性

文献综述归纳

研究路线

对比评测综合

总结不同评测选择（如攻击模板、奖励设计、UQ 估计器）如何影响跨 GUI 智能体论文的结论，揭示系统性弱点，例如领域条件化安全性或选择性 UQ 迁移。

尚未覆盖：由于接口、模型访问和任务粒度不同，比较结果常常不兼容；尚无统一框架将安全性、完成度和不确定性等评测维度整合为单一的可靠性画像。
分类体系与路线图综合

通过引入针对性基准，隐式地将 GUI 智能体领域划分为多个能力轴（视频定位、长时域规划、安全性、欺诈检测），但尚未提供基于证据的明确智能体子问题分类。

尚未覆盖：新出现的能力聚类是否全面且稳定，以及系统综合能否优先排序哪些能力缺口阻碍了下游进展，仍然未解决。
开放问题与缺口映射

每个基准都凸显了具体失败模式：欺诈检测中的良性召回崩溃、领域条件化安全脆弱性、噪声诱导的奖励退化、跨模型 UQ 迁移弱，有效将广泛文献转化为可操作的研究问题。

尚未覆盖：缺口的优先排序缺失；缺乏成本-收益模型或共享元评测，无法判断改进某一方面（如 RL 中的噪声校正）是否比解决另一问题（如长时域上下文管理）带来更多整体进展。

研究共性

  • GUI 智能体在分布偏移下仍表现出系统性失败，没有领域特定的加固，它们对于高风险部署不安全。
  • 自主或可验证评估对于扩展智能体训练和基准测试至关重要，但当前评估器存在噪声，其反馈必须经过校准。
  • 不确定性量化是一种有前景的安全层，但其有效性高度依赖于模型架构和接口，在模型层级之间不能稳健迁移。
  • 长时域和视频引导任务需要超越被动历史累积的更好上下文管理，主动上下文动作带来的收益证明了这一点。

关键差异

  • 安全机制在不同威胁模型上被评估：手工提示注入与技能注入，导致对智能体鲁棒性得出相反的结论。
  • 奖励粒度不同：一些工作使用终端二元任务成功反馈，而另一些依赖每步或可验证的执行结果，影响探索和信用分配的类型。
  • 交互模态：基于浏览器的智能体、移动 GUI 智能体和视频引导智能体被作为独立设置处理，尚无跨模态基准测试以验证一个模态的进展是否能迁移到另一个。
  • 评估粒度：一些基准专注于单步基础精度，而另一些衡量多步任务完成情况，使得对智能体能力的直接比较模糊。

开放问题

  • 能否设计一个统一的评估协议，同时衡量任务完成、安全性和不确定性，并适用于开源权重和闭源智能体？
  • 已识别的失败模式（如良性召回崩溃、领域条件化安全）会如何随着底层模型规模扩大或通过 RL 微调而演变？
  • 鉴于当前评估的脆弱性，保证泛化到真实世界 GUI 智能体部署所需的最小基准任务集是什么？
