研究路线

真实 GUI/OS 任务与环境设计

构建共享任务或环境，比较真实桌面、短视频动态界面和视频引导交互中的 GUI 代理；例如 MacAgentBench、LivingScreen、VG-GUIBench。

尚未覆盖：动态界面类型、多步轨迹、跨平台迁移以及任务分布与真实部署的一致性仍缺少证据。
指标与压力测试设计

通过多检查点评分、成本-准确性/观察控制、子目标完成度以及后验不确定性/共形评估，揭示总分以外的能力。

尚未覆盖：代理指标与用户决策风险是否一致，跨模型层级/界面是否稳定，分布偏移下是否鲁棒。
面向共享基准的代理能力方法

通过多模态技能库、证据驱动 harness 编辑、可验证在线 RL 任务合成、弱监督视觉定位或任务感知关键帧提取提升代理能力，并在 OSWorld、ScienceBoard、CUA-World 等基准上验证。

尚未覆盖：基准提升能否迁移到保留集和部署环境；训练与冻结模型适配的成本收益；部分论文缺少局限或工件细节。
可比基线与报告规范

通过统一基线、框架/模型比较和代码、数据集、仓库等工件信号提升结果可审计性。

尚未覆盖：结论在不同实现和算力预算下是否稳定；若干论文局限字段为空或工件不完整，复现性仍有缺口。

研究共性

  • 规则或确定性评估常用于提升基准可复现性；细粒度检查点能揭示总分掩盖的代理差异。
  • 当前代理在动态或长程交互中表现出过度观察、观察不足和不确定性校准弱等共性失败模式。
  • 技能库、harness 编辑、弱监督等冻结模型或数据高效方法可在不重训整模型的情况下获得明显基准提升。
  • 代码与数据集发布较常见，但部分论文未提供可见局限，证据质量不均衡。

关键差异

  • 评测目标：单步可执行 GUI grounding 与多步计算机使用轨迹被分别处理，难以直接比较。
  • 界面设置：静态桌面/应用工作流不同于短视频或视频引导任务，后者更依赖观察控制。
  • 改进路径：在线 RL、弱监督等训练方法与冻结模型的技能/harness 适配形成不同路线。
  • 指标：总分、成本-准确性、子目标完成度、不确定性/共形排序代表不同优先级，可能产生不同排名。

开放问题

  • 当前基准任务分布是否覆盖 GUI 代理预期工作的动态、长程和跨平台场景？
  • 哪些细粒度或风险感知指标更贴近真实部署决策，并在什么条件下与 Pass@1 偏离？
  • 不确定性排序和共形覆盖能否跨模型类别、接口和分布偏移迁移，而不需目标特定重排序？
  • 技能库、harness 优化或 RL 的收益在保留集、框架和算力预算下是否稳定？
  • 当前证据中缺失的复现与局限细节是否隐藏了结果边界？

method

59 方法质量 100 近期性 40 可复现性 40 主题相关性

文献综述归纳

研究路线

弱监督与交互数据驱动的 GUI 策略训练

利用未标注截图、网页或拖拽交互数据降低昂贵人工标注依赖，进行视觉定位与动作预测；通过小规模高质量标注和强化学习进行校准。

尚未覆盖：跨应用、跨平台和多步轨迹泛化大多未被证明；局限性常未报告，负面结果与失败边界不清。
可验证任务合成、在线 RL 与执行 harness 自改进

通过可验证任务生成、按学习前沿分配 rollout、以及围绕冻结模型优化执行 harness 来扩展计算机使用智能体能力，在 OSWorld、ScienceBoard、WindowsAgentArena 上取得提升。

尚未覆盖：模型、规划器/harness、任务先验与数据之间的贡献归因尚不明确；评测集中在少数基准，且缺少 limitations 说明影响泛化信心。
GUI grounding、观察控制与交互基准评测

衡量真实桌面 GUI+CLI、动态短视频、视频引导任务、拖拽交互以及后验不确定性量化，揭示 Pass@1 之外的子目标、效率和 grounding 失败。

尚未覆盖：平台和交互类型覆盖碎片化；跨模型层级/接口的 UQ 排名迁移较弱，分布偏移下 conformal coverage 下降，多步轨迹尚未充分评估。
面向视频引导任务的关键帧提取

通过选择任务相关且场景动态的关键帧压缩视频证据，改善视频问答和视频引导 GUI 交互任务表现。

尚未覆盖：证据限于视频问答和少量 GUI 任务，与规划器及更广泛动态智能体环境的结合仍待验证。

研究共性

  • 单一 Pass@1 不足以比较 GUI 智能体；子目标完成、成本准确率、grounding 误差、关键帧增益和不确定性排名迁移等细粒度指标能暴露隐藏差异。
  • GUI 特定训练或适配可提升计算机使用能力，包括弱监督 grounding、交互数据集、可验证 RL 任务、关键帧选择和冻结模型 harness 优化等路径。
  • 当前智能体存在观察控制缺口：过度观察或观察不足，且 grounding 不确定性排名在数据集、模型和接口间仅选择性迁移。

关键差异

  • 干预位置不同：一些方法通过弱监督或强化学习更新模型权重，另一些冻结骨干模型，仅优化执行 harness 或输入关键帧提取。
  • 评测目标不同：桌面多应用任务、动态短视频流、视频引导指令跟随、拖拽交互和单步 grounding 不确定性各自强调不同的能力边界。
  • 监督与可验证性假设不同：弱监督需要极少量标注但可能依赖 RL 校准；在线 RL 依赖可验证任务目标；harness 优化依赖重复运行和截图证据；不确定性评测依赖模型内部状态。

开放问题

  • 弱监督、harness 优化和 RL 训练的 GUI 智能体能否跨未见过应用、操作系统、动态界面和多步轨迹泛化？
  • 什么评测协议能分离模型贡献与 harness 设计、技能库、任务先验和训练任务合成的影响？
  • 在哪些条件下 GUI grounding 不确定性排名和共形点击区域可跨模型层级与接口迁移，而无需目标特定重校准？
  • 当前证据偏点击/单步 grounding，如何评测观察控制、拖拽和动态交互的多步任务？

theory

Formal analysis, task abstractions, interaction theory, or reliability/safety framing for GUI agents

59 方法质量 100 近期性 40 可复现性 41 主题相关性

文献综述归纳

研究路线

面向不同界面类型的可执行GUI任务抽象与评测

为macOS GUI+CLI工作流、动态短视频界面和拖拽原语定义任务套件，采用基于规则的、可验证的或成本-准确性评分，超越仅看端到端成功率。

尚未覆盖：覆盖范围仍限于特定平台或交互类型；动态观察控制和拖拽定位尚未被形式化为通用代理能力，部分记录缺少局限性说明。
面向冻结代理的外部脚手架与知识增强

通过提供多模态按应用技能库，或基于重复运行证据诊断并编辑执行harness，在不训练骨干模型的情况下提升性能。

尚未覆盖：在已评估应用和基准之外的迁移仅部分得到检验，尤其是对未见界面和交互类型的边界仍不明确。
面向GUI代理训练的任务合成、弱监督与在线RL

通过可验证合成任务与前沿采样，或大规模未标注截图上的视觉定位加少量标注校准，降低标注成本并扩展计算机使用训练。

尚未覆盖：证据集中在OSWorld、ScienceBoard等基准；对动态屏幕、拖拽交互和分布偏移下失败预测的泛化尚不明确。
面向可靠GUI定位的后验不确定性量化

评估GUI定位中不确定性方法的排序与空间校准，识别稳定的开放权重方法族，并在校准条件下缩小共形点击区域半径。

尚未覆盖：结论仅限于单步定位；跨模型和跨接口的排序迁移较弱，校准-测试或接口失配下覆盖率下降。

研究共性

  • GUI代理研究正从粗粒度成功率转向细粒度、可验证和成本感知的评测信号。
  • 冻结模型无需重训练即可通过改变外部脚手架（包括多模态技能检索和harness逻辑）获得提升。
  • 训练阶段扩展越来越依赖合成、弱标注或可验证交互数据，而非纯人工标注。
  • 非静态界面和非点击交互原语暴露出独特失败模式，如过度/不足观察和拖拽定位较弱。

关键差异

  • 干预层级不同：修改执行harness或技能工件，对比通过RL或弱监督训练代理，对比后验不确定性校准。
  • 评测单元不同：有的衡量完整计算机使用任务完成，有的衡量单步定位、拖拽原语或动态平台成本-准确性。
  • 监督与数据不同：有的依赖重复执行和截图诊断，有的扩展可验证合成任务，有的利用大规模未标注截图；这改变了效率和泛化主张。
  • 部署场景不同：桌面macOS多应用工作流、浏览器短视频平台、合成Docker任务、GUI定位数据集和Windows迁移是不同的上下文，因此基准收益可能不直接迁移。

开放问题

  • 细粒度子目标和成本-准确性信号是否会在与Pass@1相比时改变模型排名，哪个信号应指导实际部署？
  • 技能库或harness层面的收益能否在未见的应用、动态界面和非点击原语上无需任务特定整理即可迁移？
  • 不确定性排序和共形校准在模型族、界面和分布偏移变化下需要满足什么条件才能保持可靠？
  • 对于内容在动作之间变化的动态屏幕界面，应如何形式化观察控制，并以什么指标衡量信息获取效率？
  • 许多可见记录缺少局限性、代码或数据集细节；这些应视为验证缺口而非不存在证据，使可复现性和边界问题保持开放。

system

59 方法质量 99 近期性 40 可复现性 43 主题相关性

文献综述归纳

研究路线

可运行的 harness 原生智能体训练与部署栈

通过拦截模型调用并在隔离容器中执行 rollout，将基于工具/harness 的智能体转化为可训练策略，覆盖 GUI 与计算机使用环境。

尚未覆盖：错误恢复仍弱；harness 设计显著影响可训练性；在 Kubernetes/编排环境之外的独立部署未充分验证。
面向 GUI 控制的高效动作策略架构

通过潜空间候选评分、块级扩散或未标注截图弱监督降低推理成本和数据需求。

尚未覆盖：速度提升常以准确率为代价；证据多限于 AndroidControl 等分布内平台，广泛 GUI 泛化未解决。
面向计算机使用智能体的多模态技能与工件库

提供保留视觉图形并按需加载的可复用分层技能，以改进 UI 元素识别和工作流状态验证。

尚未覆盖：跨应用可扩展性以及技能/工件在不同智能体和环境间迁移未充分证明。
可靠性与个性化诊断

形式化恢复一致性并诊断偏好导致的分阶段执行失败，揭示整体任务成功率之下的隐藏能力瓶颈。

尚未覆盖：当前智能体仍未充分释放恢复能力；Ranking/Process 偏好处理仍较低，干预只能部分弥补。

研究共性

  • 领域正汇聚到可端到端训练的 GUI/计算机使用智能体，并以可执行、可验证的交互式基准而非静态 VQA 进行评估。
  • 来自截图或保留图形的多模态视觉 grounding 被视为识别 UI 元素和验证状态的重要手段。
  • 训练方案多结合监督微调、强化学习或自监督预训练，并常在真实或仿真环境中执行。
  • 错误恢复与用户偏好等可靠性维度开始成为独立评测目标，证据显示当前智能体在这些方面仍表现不足。

关键差异

  • 动作表示不同：潜空间候选评分、块级扩散生成、harness/工具调用、GUI+代码统一动作空间，导致不同的延迟、参数和控制权衡。
  • 监督与数据重点不同：未标注截图弱监督、可验证环境奖励的 RL、编写的多模态技能文档作为辅助上下文。
  • 评测焦点不同：整体任务成功基准、注入错误后的恢复一致性、分阶段偏好个性化诊断。
  • 部署设置不同：移动端、桌面原生、Web 与 harness 中介环境对可观测性、回滚和可复现性假设不同。

开放问题

  • 如何让 GUI 智能体在保持潜空间或非自回归策略速度与参数效率的同时，弥合相对微调 VLM 基线 86-92% 的准确率差距？
  • 哪些训练与环境设计选择能让错误恢复和偏好敏感行为端到端提升，而不是停留在潜在或部分解决状态？
  • OSWorld-Verified、AndroidControl、WebVoyager 上的成功在多大程度上迁移到未见平台、应用和用户特定工作流？
  • 为何屏幕动态预训练未提升潜在预测器决策性能，这对 GUI 智能体的预训练目标意味着什么？

研究路线

平台与交互特定GUI基准

评测桌面OS、动态短视频、拖拽和视频引导任务中的代理，揭示静态点击成功之外的失败模式。

尚未覆盖：每个平台或交互的覆盖仍较稀疏；这些基准尚未证明跨领域迁移或真实用户工作流有效性。
计算机使用代理的可复用技能与重放

通过存储多模态技能工件或把成功运行编译为带屏幕检查的状态机，改善重复任务效率和UI定位。

尚未覆盖：UI更新、任务变化和未见应用状态下的稳健性；存储时验证与回退依赖独立检查和屏幕匹配。
面向GUI定位的模型训练与架构

通过微调或块级扩散把视觉语言模型适配到定位、导航、拖拽和视频引导交互。

尚未覆盖：在生成或基准特定数据上的训练收益能否跨平台、交互类型和真实工作流迁移仍不确定。
可扩展环境与轨迹生成

重建基于源的Web环境或视频引导任务套件，以生成大规模交互和训练语料。

尚未覆盖：每个站点需要初始设置或授权，自动验证器的保真度不能保证真实任务成功或安全运营结果。

研究共性

  • GUI代理评测正从静态网页或移动点击任务扩展到桌面OS、动态视觉信息流、拖拽交互和视频引导工作流。
  • 细粒度或成本感知评价是必要的，因为总体成功率会掩盖子目标完成、观察效率和信息成本差异。
  • 技能、可重放程序、生成环境或交互轨迹等可复用工件能提升代理性能、速度或下游微调效果。
  • 前沿多模态代理在动态观察控制、多应用复杂工作流和专门手势上仍然失败。

关键差异

  • 基准平台与交互范围：静态确定性桌面GUI+CLI任务、动态屏幕信息流、拖拽定位和视频引导任务各有侧重。
  • 改进策略：外部多模态技能检索、将成功运行编译为快速状态机、训练或微调模型权重、生成环境与轨迹，路径不同。
  • 评测目标：任务成功率、子目标完成、成本-准确性信息效率、环境保真度和重复任务速度不可互换。
  • 部署设置：部分工作假设代理框架具备MCP工具访问或技能库，另一些需要每站点设置或授权，或训练专用视觉语言代理。

开放问题

  • 能否学习或脚手架化观察控制，以避免动态界面中的过度观察和观察不足？
  • 桌面、拖拽、动态屏幕和Web环境的改进能否跨应用、OS版本和真实用户工作流迁移？
  • 当UI布局、任务目标或应用状态变化时，存储技能和重放程序有多稳健？
  • 在生成或交互特定数据上微调，是否改善真实计算机使用结果，而不仅是基准特定指标？
  • 多篇方法缺少可见代码、数据集、限制和复现性验证信号，这些证据缺口如何影响结果可信度？

在冻结骨干模型上优化执行harness，或把RL rollout分配到可验证任务，而无需完全替换模型。

尚未覆盖：已报告的迁移提升仅限于少数套件；训练成本和失败模式覆盖仍缺乏充分证据。
高效动作策略与上下文管理

通过在潜空间中对候选动作评分或显式管理移动端智能体记忆，降低推理成本或避免上下文塌缩。

尚未覆盖：潜空间策略准确率低于大型VLM基线；在给定移动基准之外的长程泛化尚未建立。

研究共性

  • 评测通常由基准驱动，报告模型适配后的任务成功率或定位准确率。
  • 将视觉截图与结构化界面状态、执行结果结合是反复出现的性能提升来源。
  • 近期论文强调长程计算机使用和移动任务，以及可验证或环境派生的反馈，而不是仅做静态单步预测。
  • 方法论文经常同时提出模型或系统与新的数据集或基准，以证明留出集上的提升。

关键差异

  • 监督来源不同：桌面密集标注、可验证RL任务合成、harness观测到的失败证据和移动轨迹标注各自依赖不同假设。
  • 部署目标不同：有的优化移动AndroidControl任务，有的面向桌面OSWorld或ScienceBoard、网页欺诈或视频引导GUI交互。
  • 效率与准确率取舍不同：潜空间动作评分换取速度和更少参数，但未匹配大型VLM准确率；RL和harness方法则追求更高任务成功。
  • 评测可控性不同：欺诈检测刻意移除信誉捷径，而桌面和RL基准使用可执行环境反馈，结论依赖评测设置。

开放问题

  • OSWorld、ScienceBoard、AndroidControl或合成桌面条件上的提升能否跨模型层级和真实界面迁移？
  • 哪种监督或奖励信号能产生通用的GUI智能体能力，而不会带来基准特定伪影？
  • 如何将不确定性量化从单步定位扩展到分布偏移下的长时程智能体轨迹？
  • 证据驱动的harness优化是否覆盖足够多的失败模式，以支撑关于自改进的调研级结论？
  • 在潜空间策略证据中，屏幕动态预训练未带来决策收益意味着什么，对高效GUI策略有何启示？
