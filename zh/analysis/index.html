GUI/web/mobile/OS automation datasets, environments, tasks, metrics, and benchmarks

58 方法质量 100 近期性 40 可复现性 40 主题相关性

文献综述归纳

研究路线

真实 GUI 与 OS 任务/数据集设计

引入共享的桌面、浏览器、动态短视频与视频引导环境和任务，使代理能力在真实设置而非合成单步屏幕上可比。

尚未覆盖：对界面类型、长程多应用工作流、观察控制动态和人类级成本-准确性的覆盖仍不完整。
细粒度指标与诊断/压力测试设计

在总分之外检验子目标完成、Pass@1 与子目标差异、成本-准确性、观察行为及校准不确定性/共形区间。

尚未覆盖：这些代理指标是否与下游用户决策一致，以及不确定性/诊断排名能否不重新评估就跨模型层级和接口迁移。
基于脚手架与训练的代理改进

通过多模态技能库、证据驱动的 harness 优化、可验证 RL 任务合成和来自未标注截图的弱监督提升代理表现。

尚未覆盖：跨实现与算力预算的稳定性、基准特定过拟合，以及这些收益在评测基准之外能迁移多少。
视频引导与动态屏幕的观察/关键帧方法

通过形式化观察控制和任务感知关键帧提取处理动态内容变化，支持视频引导 GUI 任务。

尚未覆盖：证据主要限于短视频或 VideoQA/GUI 设置；更广泛的动态界面和多步代理轨迹仍缺乏验证。

研究共性

  • 近期工作认为总体成功率不够，增加子目标、成本-准确性、观察或不确定性诊断。
  • 真实任务和动态界面设置暴露当前代理行为与人类级控制之间的差距。
  • 显著提升可来自脚手架、技能、harness 或训练数据，而非仅更换骨干模型，但需要迁移证据。
  • 若干基准提供了数据集/环境和评测协议，但缺失局限性细节与跨设置验证，仍是核实性缺口。

关键差异

  • 评测对象不同：单步可执行 GUI 定位、多步桌面工作流，以及动态屏幕或视频引导任务。
  • 改进信号不同：多模态视觉技能工件、可执行 harness 编辑、可验证 RL 任务合成和未标注截图弱监督代表不同数据与监督假设。
  • 交互/部署设置不同：真实 macOS 桌面、浏览器模拟短视频平台、OSWorld/ScienceBoard/WindowsAgentArena 类环境和视频引导 GUI 任务不可直接互换。
  • 指标侧重不同：任务成功/检查点评分、成本-准确性、不确定性排名/共形覆盖，以及视频问答/代理增益分别优化不同评价目标。

开放问题

  • 细粒度基准指标是否预测用户在可控性和观察成本重要时真正关心的下游决策？
  • 基准排名和代理改进在平台、接口、模型层级与重复运行上的稳定性如何？
  • 在不同实现和算力预算下，脚手架/训练收益能否与基准特定调参区分开？
  • 动态屏幕与长程 GUI 基准如何在不过度绑定短视频等单一平台的情况下覆盖观察控制？
  • 需要补齐哪些局限性与工件证据，才能审计更广泛基准语料的复现性？

研究路线

GUI 基准与评测设计

在桌面、动态界面、拖拽和视频引导等设置中，用细粒度评分刻画 GUI 定位与计算机使用能力

尚未覆盖：覆盖受限于平台特定任务套件和短或单步片段，跨界面与长程泛化未被证实
通过监督、强化学习与自改进进行 GUI 动作预测

通过未标注截图、可验证任务合成、在线强化学习或执行框架演进，减少人工标注依赖并提升冻结或可训练模型

尚未覆盖：收益尚未与骨干模型、执行框架、任务先验或系统组件隔离，部分限制未报告
可靠性与观察感知定位

量化定位置信度、构建共形点击区域，并揭示动态界面中观察控制能力缺失

尚未覆盖：现有证据主要覆盖单步定位；跨模型不确定性迁移弱，且校准在界面或分布偏移下退化

研究共性

  • 前沿 VLM 仍存在非人类水平的可靠性缺口，如子目标失败、过度/不足观察和跨模型不确定性迁移弱。
  • 仅看 Pass@1 不够，因为成功率相近的代理在子目标、信息效率或置信度质量上可能差异明显。
  • 自改进、弱监督训练和 RL 扩展能减少对大规模人工标注的依赖并提升开源计算机使用代理。
  • 性能归因脆弱：一项研究发现技能库而非框架设计驱动最佳配置，说明系统级混淆因素很重要。

关键差异

  • 评测目标与界面不同：桌面 GUI+CLI、动态短视频、拖拽、视频引导任务和单步 GUI 定位产生不可直接比较的能力估计。
  • 改进策略不同：一方优化冻结执行框架，一方用合成任务做在线 RL，另一方从未标注截图学习视觉定位，反映不同的数据和模型访问假设。
  • 可靠性评估不同：一方关注后验不确定性排序和共形点击区域，一方关注观察成本，另一方关注细粒度任务完成，尚未形成共享的多步协议。

开放问题

  • 哪些评测维度能跨平台、跨界面和多步轨迹迁移，而不只限于特定测试套件？
  • 在限制未报告时，报告收益中有多少来自方法本身，而不是骨干模型、任务合成、执行框架或界面假设？
  • 不确定性评分和共形校准能否在开源与闭源 VLM 家族间以及真实 GUI 部署偏移下保持有效？
  • 需要何种观察控制或记忆机制来减少短视频平台等动态界面中的过度与不足观察？
  • 能否将拖拽、视频引导和桌面 GUI 基准统一为共享的动作定位评测，同时保留各自有效性？

theory

Formal analysis, task abstractions, interaction theory, or reliability/safety framing for GUI agents

58 方法质量 100 近期性 39 可复现性 40 主题相关性

文献综述归纳

研究路线

基于基准的任务抽象与能力标注

通过真实多应用任务套件和细粒度或成本感知指标，界定可观测的 GUI 智能体能力。

尚未覆盖：任务采样能否迁移到部署分布和动态界面尚不明确；细粒度子目标指标与任务成功之间的形式关系缺失。
多模态知识与可复用技能库

将应用工作流编码为可检索的多模态工件，以减少探索性交互并改善 UI 识别。

尚未覆盖：视觉技能工件能否跨应用版本或界面泛化，以及其效果如何依赖模型特定的感知误差。
证据驱动的 harness 演进与自改进

从重复运行中诊断反复出现的失败模式，并在保持骨干模型冻结的情况下优化执行脚手架。

尚未覆盖：迁移证据仅限于已测试基准，且缺少 harness 编辑后安全行为的形式保证。
基于可验证或弱监督的可扩展训练

通过合成可验证任务或使用未标注截图进行定位和强化学习，减少标注与计算负担。

尚未覆盖：缺少直接验证，证明学习策略在未见工作流上可靠且不会过拟合到狭窄的可验证奖励检查。

研究共性

  • GUI 智能体评测正在从单应用成功率转向真实、多应用和细粒度或成本感知评分。
  • 视觉定位与界面感知是核心瓶颈，保留视觉信息或从截图学习定位会改善性能。
  • 数据与任务合成、弱监督和可验证奖励正在成为提升 GUI 智能体的主要路径。
  • 可靠性被操作化为不确定性量化、故障模式诊断或空间安全区域，而不是形式安全属性。
  • 冻结模型可以通过技能库或优化执行 harness 等外部脚手架获得显著提升。

关键差异

  • 评测目标不同：单步定位、多步交互工作流、以及拖拽等特定交互原语。
  • 改进层级不同：修改冻结模型的技能或 harness，与通过强化学习或弱监督更新模型参数。
  • 界面假设不同：静态确定性桌面任务与动态连续变化界面，导致不同的失败归因。
  • 监督信号不同：人工标注或生成的可验证任务、未标注截图、可执行环境检查。
  • 可靠性表述不同：后验不确定性排序、共形空间安全、证据驱动故障模式诊断。

开放问题

  • 当平台和界面动态变化时，细粒度多检查点评分与真实部署任务成功之间关系如何？
  • 动态界面中的观察控制失败能否被形式化，并跨交互模态改进？
  • 在跨界面分布偏移下，不确定性排名迁移能否在多步智能体轨迹中保持稳定？
  • 技能库和 harness 优化能否跨应用版本泛化，而不依赖平台特定假设？
  • 可验证训练任务或 harness 编辑与未见 GUI 工作流上的安全行为之间存在何种保证？

文献综述归纳

研究路线

端到端智能体训练与编排栈

在可执行环境中训练使用推理框架或统一 GUI/代码动作空间的智能体，采用强化学习或混合监督。

尚未覆盖：错误恢复在 RL 后仍弱；推理框架设计影响可训练性；跨团队、跨基础设施复现尚未建立。
高效动作策略与服务

通过潜空间评分或块级扩散生成降低 GUI 动作选择的推理延迟或参数规模。

尚未覆盖：效率可能与精度和泛化相权衡；除 AndroidControl 和有限 GUI 基准外证据不足；部分局限未说明。
弱监督与数据高效学习

从大规模未标注截图学习 GUI 智能体，减少昂贵人工标注。

尚未覆盖：小规模校准数据之外的泛化，以及更广监督预算下的对比证据不充分。
可复用多模态技能与工件

提供分层多模态技能知识，在工件中保留视觉图形以辅助 UI 元素识别与工作流验证。

尚未覆盖：所报告基准之外的覆盖和跨应用独立复用仍不确定。

研究共性

  • GUI/计算机使用控制越来越被视为可学习多模态策略，而不是固定的提示与工具脚手架。
  • 训练信号质量、动作表示和评测环境选择会显著影响智能体成功。
  • 来自截图或保留图形的视觉 grounding 信号可改善 UI 元素识别和任务执行。
  • OSWorld-Verified、AndroidControl、WebVoyager、OSExpert-Eval 等基准常见，但尚不足支撑跨平台结论。

关键差异

  • 监督策略从海量未标注截图弱监督，到可验证混合监督加在线 RL，差异明显。
  • 动作生成方式不同：潜空间候选评分、块级扩散、自回归 VLM 输出与统一 GUI/代码动作均被提出。
  • 评测目标不同：总体任务成功、恢复一致性、偏好个性化或延迟-精度效率。
  • 部署设置不同：移动、Web、桌面 Linux 与 Windows 智能体面临不同状态、动作与回滚约束。
  • 一些系统训练实际部署的推理框架，另一些训练独立策略，使得框架特定可训练性成为未定边界。

开放问题

  • 高效潜空间或扩散 GUI 策略如何在 AndroidControl 等窄基准之外缩小精度差距？
  • 当当前智能体未能利用潜在恢复能力时，哪些训练信号或类重置机制能教会可靠错误恢复？
  • 哪种监督组合能在标注成本、可验证性和 Web/移动/桌面/Windows 泛化之间取得平衡？
  • 多模态技能工件和行为记忆日志如何在更大任务分布上泛化，证据选择如何改进？
  • 哪些推理框架和基础设施设计是跨团队、跨部署复现智能体训练所必需的？

研究路线

跨应用桌面与操作系统任务基准测试

评估GUI智能体在真实macOS桌面任务中跨多个应用的GUI与CLI操作能力，并提供细粒度子目标评分。

尚未覆盖：macOS特定指标能否迁移到其他操作系统、动态界面和长周期专业工作流。
面向计算机使用智能体的多模态技能与可复用工作流记忆

通过检索分层多模态应用技能或将成功运行编译为状态机重放，提升智能体的任务成功率和执行速度。

尚未覆盖：存储技能或程序在界面更新、新任务变体和跨应用迁移下的鲁棒性。
动态与专门化GUI交互基准测试

覆盖短视频动态屏幕、视频引导GUI任务和拖拽交互，衡量任务准确性与观察效率。

尚未覆盖：超出所选平台和交互类型的泛化，以及当前模型缺乏观察控制的原因。
高效或生成式GUI智能体模型训练

训练块级扩散视觉语言智能体完成GUI定位和导航，作为自回归生成的替代范式。

尚未覆盖：扩散范式在更广移动、桌面和网页任务及部署延迟约束下能否匹配或超过前沿模型。

研究共性

  • 真实GUI评估需要可执行、面向应用的环境，而不仅是静态截图。
  • 前沿智能体在观察控制、细粒度定位或专门化交互上仍失败，因此仅看任务成功并不足够。
  • 多模态技能、编译的状态机程序或生成轨迹等可复用结构化知识可以提升任务成功率、速度或下游微调效果。
  • 评估正在扩展到点击以外的交互类型与效率维度，包括拖拽、视频引导、GUI+CLI和动态内容。

关键差异

  • 评测目标不同：一次性Pass@1、成本-准确率或观察效率、子目标完成和重复任务速度不能互换。
  • 环境范围不同：固定macOS桌面应用、模拟短视频平台、重建的真实网站和视频引导交互强调不同的失败模式。
  • 改进策略不同：检索增强的多模态技能记忆、运行编译为状态机、生成式模型训练以及环境或轨迹构建针对各自不同瓶颈。
  • 交互模态假设不同：一些评测以静态界面为前提，另一些则采用动态、拖拽、视频引导或GUI/CLI组合工作流。

开放问题

  • 特定平台基准上的收益能否迁移到跨操作系统、跨应用版本的真实专业工作流？
  • 对于内容在动作之间变化的动态界面，应如何学习或评测观察控制能力？
  • 当应用界面变化、任务变化或智能体遇到未知工作流时，已存储技能和编译程序有多鲁棒？
  • 从真实网络重建的环境能否保持足够保真度，使微调后的智能体在真实网站上既有效又安全？
  • 数据包中部分方法缺少公开代码、数据集、模型检查点或局限性说明，这些验证缺口如何影响结论？

研究共性

  • 可见的高排名工作将 GUI/计算机使用智能体作为核心对象，贡献基准、训练方法或评测流程，而非综述式综合。
  • 常见模式是将 VLM 或 LLM 智能体与受控环境或数据集配对，并报告在定位、任务完成、动作选择或不确定性质量上的提升。
  • 自动生成或可验证证据反复出现：密集桌面标注、可验证 RL 任务、重复运行界面变化以及不确定性校准都被用作训练或评测信号。

  • 表示方式不同：结构化 UI 字段与无障碍树、基于截图的潜表示、以及视频关键帧选择。

  • 评测目标不同：有的关注单步定位或不确定性，有的关注长程移动/桌面任务完成、欺诈召回或推理延迟。
  • 部署场景不同：桌面、移动、网页和视频引导任务产生不同的动作空间、状态观测和失败模式。
