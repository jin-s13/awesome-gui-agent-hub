benchmark

GUI/web/mobile/OS automation datasets, environments, tasks, metrics, and benchmarks

61 方法质量 99 近期性 38 可复现性 44 主题相关性

文献综述归纳

研究路线

真实桌面与OS任务构建

提供可执行macOS与OS任务、确定性规则评分和细粒度子目标检查点。

尚未覆盖：应用、OS版本与动态工作流的覆盖未验证，局限性信息常常缺失。
动态与视频引导基准环境

引入界面变化和视频引导任务，检验观察控制与信息效率。

尚未覆盖：LivingScreen局限于短视频平台；视频引导基准局限细节缺失，更广动态界面覆盖未验证。
不确定性与指标压力测试

跨多模型多数据集评估GUI grounding的后验不确定性与空间校准。

尚未覆盖：证据仅限于单步grounding，未覆盖多步轨迹；跨模型与跨接口迁移弱，分布偏移下覆盖下降。
基于基准套件的智能体与harness改进

通过技能库、harness优化、可验证任务合成和弱监督提升冻结或开源智能体。

尚未覆盖：迁移证据限于选定套件；多数局限性为空，鲁棒性与边界条件未明。

研究共性

  • 可执行基准任务在多个开源与闭源模型上评测，确定性或可验证评分是主要目标。
  • 总分不足以反映能力；细粒度子目标、成本-准确性、观察与不确定性诊断被用于揭示隐藏失败。
  • 当前智能体在动态或多步设置下尚未达到人类水平，跨设置迁移或校准较弱。
  • 多数论文提供代码、数据或工件线索，但局限性部分常缺失，方法边界难以审计。

关键差异

  • 评测场景不同：macOS桌面GUI+CLI、浏览器短视频、视频引导GUI交互、容器化OS任务与单步GUI grounding。
  • 优化手段不同：基准设计、多模态技能检索、执行harness编辑、可验证RL任务合成、弱监督grounding或不确定性校准。
  • 指标侧重不同：Pass@1与子目标完成、成本-准确性信息效率、不确定性排序与覆盖率。
  • 部分工作仅观察基准表现，部分直接改变训练或执行，导致贡献之间的可比性间接。

开放问题

  • 细粒度与不确定性诊断能否标准化，使基准结论无需目标特定重排即可迁移？
  • harness、技能和RL的提升能否在未见OS版本、动态界面和更长多步工作流中保持？
  • 当观察成本、校准偏移和执行变异性存在时，哪些代理指标更符合用户决策质量？
  • 鉴于部分局限性缺失、复现信号不均，需要哪些报告与工件要求？

method

GUI agent models, planning, grounding, action prediction, training, or reasoning methods

61 方法质量 100 近期性 38 可复现性 44 主题相关性

文献综述归纳

研究路线

真实GUI智能体基准与任务设计

在macOS桌面、动态短视频和拖拽交互上测量VLM智能体能力，暴露观察控制、技能使用和动作覆盖缺口。

尚未覆盖：证据集中在特定平台和交互类型；成本-准确性、子目标指标和跨基准迁移仍不统一。
GUI智能体训练与自改进方法

通过弱监督、可验证任务合成、在线RL或冻结骨干模型的harness优化，降低标注成本并提高成功率。

尚未覆盖：收益难以归因于方法本身而不是基座模型、框架、技能库或harness；OSWorld、WindowsAgentArena和ScienceBoard之外的迁移证据不足。
GUI控制的视觉定位与输入表示

通过关键帧提取、拖拽动作覆盖和点击区域校准，处理视频引导任务、拖拽定位和有依据的不确定性。

尚未覆盖：动态内容下的观察控制、跨模型与跨界面UQ迁移以及多步定位仍未解决。

研究共性

  • 当前GUI智能体工作默认以VLM作为决策模型，并通过环境中的任务完成评估，而不只是静态UI理解。
  • 论文普遍认为真实和动态GUI任务会暴露静态点击基准看不到的失败，尤其是观察策略、执行可变性和动作原语覆盖。
  • 多种方法从人工标注转向可扩展监督或自改进，利用截图、执行轨迹、可验证任务合成或harness编辑。
  • 评估越来越多采用确定性检查、细粒度子目标评分或成本-准确性权衡来区分通过率和能力差异。

关键差异

  • 有些工作侧重通过基准揭示能力边界的测量，另一些则侧重通过训练、RL或harness优化改进行为。
  • 监督假设不同：未标注截图加少量校准数据、可验证合成任务、冻结模型harness编辑和拖拽数据微调是相互竞争的路线。
  • 交互范围在点击定位、GUI+CLI、短视频动态内容和拖拽动作之间不同，发现不能自动跨界面迁移。
  • 评测目标从单步定位与不确定性或共形区域到多步桌面任务完成，不同目标暴露不同失败模式。
  • 闭源模型因内部状态不可访问，需要与开源权重模型不同的UQ或适配策略。

开放问题

  • 报告在OSWorld类或桌面基准上的提升中，有多少来自训练或harness方法本身，而不是技能库、框架选择或基座模型能力？
  • 能否学习或内置观察控制，以在动态屏幕上减少过度观察和观察不足而不损失任务准确性？
  • 拖拽和GUI+CLI定位改进能否泛化到下游多步计算机使用任务？
  • 在模型和界面变化时如何选择或适配不确定性量化，鉴于跨层级UQ排名转移较弱？
  • 除了已研究的macOS、短视频、拖拽和OSWorld风格环境，哪些证据能证明跨操作系统、应用集和交互模态迁移？

theory

Formal analysis, task abstractions, interaction theory, or reliability/safety framing for GUI agents

61 方法质量 100 近期性 38 可复现性 44 主题相关性

文献综述归纳

研究路线

交互覆盖与任务抽象基准（如 MacAgentBench、LivingScreen、DragOn）

把评估从静态点击扩展到复合GUI+CLI桌面任务、动态短视频界面和拖拽操作，并提供规则化或浏览器化评分。

尚未覆盖：多步轨迹评估、观察控制形式化、跨平台迁移，以及基准覆盖能否预测真实部署行为。
外部脚手架：技能库与harness自改进

通过分层多模态技能或基于截图的证据驱动harness优化，在保持骨干模型冻结的同时提升代理表现。

尚未覆盖：优化是否无需按目标重新调整即可跨应用/基准迁移，以及增益来自框架设计还是骨干模型能力。
数据高效与可验证的GUI策略训练

利用未标注截图的弱监督或可验证任务合成与在线RL，降低标注成本并扩展到更强完成能力。

尚未覆盖：分布偏移鲁棒性，以及合成或弱监督任务能否预测真实GUI环境中的失败和迁移。
可靠性、不确定性与安全导向评估

引入细粒度子目标指标、成本-准确率、后验UQ和共形点击区域，揭示超越pass/fail的失败模式。

尚未覆盖：多步不确定性保证、跨模型/接口UQ迁移，以及校准-测试或接口不匹配下的覆盖度。

研究共性

  • 评估应超越总体成功率，因为相似的Pass@1或任务准确率可能掩盖子目标完成、观察效率或定位可靠性的差异。
  • 冻结模型可通过技能、harness或工具等外部脚手架提升，而不必重新训练骨干模型。
  • 动态界面和非点击交互暴露当前代理在观察控制和拖拽定位等方面的明显缺口。
  • 未标注截图和可验证任务合成可减少对昂贵人工标注的依赖。

关键差异

  • 改进应发生在哪一层：部分工作通过在线RL或弱监督更新模型，另一部分保持模型冻结并改进技能库或执行harness。
  • 哪个评估目标最重要：任务完成、信息效率、不确定性排名迁移或拖拽定位，各自选择不同的主要指标。
  • 外部知识是否需要视觉图形：有路线显示多模态技能优于纯文本技能，另有路线优化代码层或harness层变化。
  • 不确定性排名能迁移多广：证据显示模型内迁移可能较强，但跨层级或跨接口迁移弱，需要按目标重新排名。

开放问题

  • 能否把单步GUI定位的后验UQ扩展到多步代理轨迹，并提供有效覆盖保证？
  • 如何形式化和改善动态短视频界面中的观察控制，因为过度观察和观察不足是主要失败模式？
  • 技能库和harness优化能否跨应用、平台和基准泛化，而无需重新优化或细粒度再验证？
  • 在何种分布偏移下，可验证任务合成和弱监督GUI训练仍能保持足够的部署可靠性与安全性？

system

Runnable GUI agent systems, frameworks, sandboxes, tool-use platforms, or orchestration layers

59 方法质量 99 近期性 38 可复现性 44 主题相关性

文献综述归纳

研究路线

面向计算机使用智能体的GUI技能与记忆复用，例如 VISUALSKILL 和 EchoPath

将经过验证的应用工作流编码为多模态技能或可回放记忆，使智能体复用流程、降低 token 与执行时间，并在运行期改善 UI 定位。

尚未覆盖：复用依赖确定性适用条件或逐应用编写；证据尚未证明跨应用、跨操作系统、实时时序和长期工件维护上的泛化能力。
Harness 原生与在线训练框架，例如 OpenForgeRL、OpenWebRL 和 GUICrafter

在真实或 harness 包装环境中训练 GUI 智能体，通过弱监督、在线多轮强化学习或拦截已部署 harness 调用降低标注成本。

尚未覆盖：训练后错误恢复仍弱；harness 设计影响可学习性；评估只覆盖数百到数千任务，跨域和跨基础设施泛化尚不确定。
面向 GUI 生成的智能体模型架构，例如 LLaDA-UI

提供基于块级扩散的视觉语言 GUI 生成范式，同时尽量保留并行解码并改善 grounding 与导航。

尚未覆盖：现有证据仅与选定的 Qwen 基线在六个基准上比较，缺少关于部署延迟、鲁棒性和更广泛可复现性的局限分析。
诊断基准与评测环境，例如 Desktop-Delta Bench 和 OSWorld-Science

在最终任务成功之外评估 GUI 过渡重构、状态验证、源跟踪、动作推断和科学软件工作流，并采用执行式评分。

尚未覆盖：离线诊断未包含异步实时动态；覆盖主要限于 Linux 桌面动作类型或选定科学领域，实时和跨操作系统有效性仍不确定。

研究共性

  • 可运行 GUI 系统通常将智能体策略与 harness 或编排层分离，使同一策略可以在多个环境中复用。
  • 训练与评测越来越依赖执行级或轨迹级成功信号，而不是只测量单帧动作定位。
  • 记忆、技能或回放工件在保留视觉和上下文信息并经过条件适用性检查时，可以显著降低推理成本并改善 grounding。
  • 弱监督或在线强化学习可以显著减少对大规模 GUI 标注数据的依赖，但需要谨慎初始化和任务成功判定。

关键差异

  • 监督策略不同：有的使用海量未标注截图加小规模高质量校准集，有的使用真实网站在线多轮强化学习或 SFT 加 RL，数据效率和基础设施成本不同。
  • 表示方式不同：面向 GUI 生成的块级扩散与 harness 包装的自回归或多模态策略在可见证据中缺少匹配训练和部署条件下的比较。
  • 记忆粒度不同：按主题组织的多模态技能库与带确定性适用检查和图像重瞄准的可回放轨迹记忆代表了不同复用假设。
  • 评测目标不同：离线步骤级过渡诊断和领域特定的科学软件任务与在线网页或桌面任务成功不等价，报告结果不可直接互换。

开放问题

  • 可复用记忆与技能工件在应用、操作系统版本和 UI 布局变化时是否仍正确，需要怎样的验证和维护？
  • 如何在不简化部署环境的前提下，将实时 GUI 时序、异步事件和错误恢复纳入训练与离线诊断？
  • 在网页、桌面、移动和科学软件环境中达到强 GUI 智能体性能所需的最小监督与基础设施预算是什么？
  • 现有代码、数据集、基准和 harness 工件是否支持独立复现，缺失的局限说明或工件信息是否构成验证缺口？

application

Domain applications of GUI agents, such as office automation, mobile apps, web tasks, software operation, or professional tools

64 方法质量 99 近期性 38 可复现性 48 主题相关性

文献综述归纳

研究路线

面向桌面、网页、移动与动态媒体的真实GUI任务基准

提供应用相关任务集和基于规则、子目标、定位或成本精度的指标，用于比较GUI代理。

尚未覆盖：跨平台与跨交互类型的覆盖仍不均匀，动态观察控制和真实可靠性仍未有结论。
多模态技能与流程知识库

将工作流和视觉参考编码为分层多模态技能或已编译状态机，以提高准确率或重复任务速度。

尚未覆盖：跨应用、界面更新和非重复任务的迁移未见证据；可视化技能收益限于已报告基准。
大规模定位数据集与模型训练流程

通过大规模截图/指代表达数据集和监督微调、D2RL或块级扩散训练提升元素定位与导航。

尚未覆盖：跨平台和跨规模的泛化，以及数据与训练算法的相对贡献仍不明确。
动态与视频GUI感知及观察控制

从动态或视频界面提取与任务相关的视觉证据，并衡量信息效率。

尚未覆盖：已识别出过度或不足观察失败，但缺少在短视频和视频引导基准之外的通用解决方案。

研究共性

  • 应用导向的评估更多报告子目标进展、定位准确率或信息成本，而非只报告最终成功率，从而暴露粗粒度通过率隐藏的失败模式。
  • 领域特定的视觉和流程信息有助于提升代理：保留视觉图形、收集拖拽或截图定位数据、在应用数据上微调都能改善表现。
  • 现有GUI代理在动态媒体、拖拽操作和多任务观察控制上仍未达到人类级别可靠性。
  • 桌面、网页、移动平台以及GUI+CLI交互被视为相互关联的代理能力面，而不是彼此独立的评估标签。

关键差异

  • 改进策略不同：推理期技能库或重放、训练期定位数据与D2RL，或模型级扩散解码。
  • 评测目标不同：最终Pass@1、子目标完成、定位准确率、成本精度/信息效率或重复任务加速。
  • 交互模式不同：静态桌面/CLI、动态短视频观察、拖拽操作、视频引导任务和重复工作流。
  • 表示与监督方式不同：多模态视觉文本技能与纯文本技能、确定性规则评分与基准特定指标、微调与已编译状态机记忆。

开放问题

  • 动态界面中的观察控制失败能否在保持任务准确率和信息效率的同时得到纠正？
  • 来自大规模交互数据集的拖拽定位提升能否迁移到保留基准之外的下游计算机使用任务？
  • 已编译重放程序对应用界面更新和细微任务措辞变化有多稳健？
  • 大规模定位数据集与D2RL式训练对跨平台泛化的相对贡献是什么？
  • 多模态技能库在CUA-World和OSExpert-Eval之外，尤其在专业工具和更长工作流上是否依然有效？

survey

Surveys, taxonomies, tutorials, position papers, or roadmap papers for GUI agents

57 方法质量 99 近期性 38 可复现性 42 主题相关性

文献综述归纳

研究路线

基准驱动的GUI评测与grounding协议

在受控GUI grounding、视频引导、诈骗检测、安全与不确定性任务上衡量智能体能力，并提供指标与基线。

尚未覆盖：覆盖仅限选定任务和接口；闭源或优化的对抗设置在证据包中常难以复现。
面向计算机使用训练的数据与可验证任务生成

通过密集标注或可验证任务改进grounding与长程策略学习，减少对人类示范的依赖。

尚未覆盖：向未见应用的迁移以及合成任务是否匹配真实分布仍只有部分证据。
面向冻结或紧凑策略的执行harness与上下文管理

通过优化可执行harness或显式记忆动作提升智能体可靠性，同时保持或使用小型模型。

尚未覆盖：长程记忆基准覆盖和跨基准迁移仍然较窄；实现工件可得性不一致。
风险、校准与安全审计

在受控或净化协议下评估不确定性校准、提示注入抵抗力和安全捷径依赖。

尚未覆盖：结论具有领域条件性和分布敏感性；覆盖有限且只有部分工件公开。

研究共性

  • GUI智能体评测分散在grounding、长程完成和风险维度上，没有单一基准覆盖所有相关行为。
  • 通过更优数据、上下文或执行harness，冻结或紧凑模型也能获得显著提升，说明非模型干预很重要。
  • 安全与不确定性结论对评测领域、接口和可用捷径高度敏感。
  • 公开工件与可复现信号不均衡，使跨论文比较依赖汇总结果而非已验证实现。

关键差异

  • 部分工作通过大规模可验证任务合成和在线RL提升能力，另一些工作避免模型训练，转而优化harness、上下文或后验校准。
  • 评测目标不同：单步grounding、长程任务完成、安全或诈骗判断之间无法直接比较最优声明。
  • 可复现证据不同：一些论文发布详细工件，另一些主要报告基准分数，形成验证缺口。
