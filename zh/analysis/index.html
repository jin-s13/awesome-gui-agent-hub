研究路线

真实操作系统与桌面任务基准

构建多应用、多步骤的共享 GUI 任务，并用确定性或规则化检查让计算机使用代理的性能可比。

尚未覆盖：现有证据集中在 macOS 桌面、OSWorld、OSWorld-Verified、ScienceBoard、WindowsAgentArena 等特定套件；跨套件稳定性和动态界面覆盖仍不确定。
动态与视频引导界面基准

在内容变化或视频指定目标下评估代理，将观察成本或关键帧质量纳入任务精度之外的评价维度。

尚未覆盖：现有证据限于短视频平台和视频引导 GUI 任务；过度观察与观察不足已被发现，但尚未成为通用评分维度。
细粒度与不确定性感知评测

揭示总分相同的子目标完成差异，并测量 GUI grounding 的后验不确定性以支持选择性预测安全。

尚未覆盖：不确定性基准证据仅覆盖单步 grounding；跨模型和跨接口排名迁移较弱，需要按目标重新评估。
在基准上验证的代理改进方法

检验技能库、harness 优化、可验证任务合成与在线 RL、未标注截图弱监督等方法能否提升基准表现。

尚未覆盖：提升常在特定基准上报告，训练预算、工件和执行 harness 不同；超出报告设置的迁移证据有限。

研究共性

  • 细粒度、规则化或多检查点评测正在替代或补充单一最终成功率。
  • 当前代理在动态界面上仍低于人类水平，尤其是当观察效率被计入得分时。
  • 基准进展通常通过多模型、多框架比较报告，而非单一模型声明。
  • 相邻方法工作把现有 GUI 基准套件作为技能、harness、RL 和弱监督提升的主要评测平台。
  • 基准工作通常报告多模型或多框架比较，但报告完整性和工件可得性在各条目间存在差异。

关键差异

  • 一些路线面向静态多步桌面任务完成，另一些要求动态观察控制或视频引导 grounding，这改变了任务分布和指标设计。
  • 单步 grounding/不确定性评测与完整多步代理轨迹评测之间存在内容层面分裂，难以直接比较。
  • 如何处理视觉上下文存在差异：保留视觉技能工件或提取任务感知关键帧都能带来提升，说明对观察成本的假设不同。
  • 报告提升归因于不同杠杆——技能库、harness 优化、在线 RL 或弱监督——但代码库和算力预算不同，改进来源尚未隔离。

开放问题

  • 细粒度多检查点和成本-精度指标是否与真实用户或企业成功一致，而不仅限于排行榜？
  • 过度观察与观察不足如何在短视频平台之外的 OS/web 基准中量化和迁移？
  • 不确定性排名跨模型家族和接口迁移弱的原因是什么，能否扩展到多步 GUI 轨迹？
  • 技能、harness、RL 和弱监督带来的提升是否在可复现数据、代码和可比算力预算下仍然成立？

method

GUI agent models, planning, grounding, action prediction, training, or reasoning methods

59 方法质量 100 近期性 40 可复现性 41 主题相关性

文献综述归纳

研究路线

跨操作系统、动态界面与交互类型的 GUI 代理能力评估

评测点击式网页任务以外的动作 grounding 与任务完成，覆盖 macOS 桌面、动态短视频屏幕、拖拽交互和单步 grounding 不确定性。

尚未覆盖：各基准仅覆盖有限平台或界面；观察到的能力与排名迁移不能保证跨 OS、界面动态、交互类型或模型层级成立。
面向 GUI grounding 与计算机使用策略的训练与数据高效方法

通过未标注截图弱监督、可验证任务合成和在线强化学习，减少对昂贵动作标注和静态指令数据的依赖。

尚未覆盖：多篇论文限制字段缺失或较简；已报告套件之外的泛化、数据污染、以及表示学习与 RL/任务生成贡献的隔离尚未验证。
执行框架优化与观察控制方法

通过优化冻结模型周围的执行框架、基于操作前后截图诊断失败，并处理动态界面中的观察不足与过度观察，提升代理表现。

尚未覆盖：执行框架、技能库和观察策略的贡献归因尚未完全隔离；冻结框架迁移仅在单一次要基准上展示，未覆盖更广动态界面场景。
视频引导 GUI 与代理任务的关键帧或观察选择

通过任务相关、场景感知的关键帧选择连接视频理解与 GUI 动作，提升 VideoQA 与视频引导代理任务表现。

尚未覆盖：GUI 交互任务的证据窄于 VideoQA；该选择器与 VG-GUIBench 设定之外的适用性尚未证明。

研究共性

  • GUI/计算机使用代理应被视为感知、grounding、动作执行与环境反馈组成的系统，评估不能只看单步 UI grounding。
  • 当前代理在观察控制和非点击或动态交互上仍存在失败，如过度/不足观察、拖拽执行弱和不确定性迁移不稳定。
  • 无完全监督轨迹的自改进方法开始获得证据：弱监督、可验证强化学习和执行框架演化能在已报告基准上提升冻结或低标注代理。
  • 基于规则或可执行指标被广泛使用，但细粒度评分显示总 Pass@1 或准确率可能掩盖子能力差异。

关键差异

  • 评测目标与部署场景差异大：真实 macOS 桌面、动态短视频、拖拽交互、视频引导 GUI 和单步 grounding 不确定性各有侧重。
  • 干预层次不同：有方法通过弱监督或在线 RL 训练模型，有方法冻结骨干并优化执行框架，还有方法改进关键帧输入选择。
  • 监督与数据假设不同：未标注截图校准、可验证任务合成强化学习、以及基于证据的 harness 编辑依赖不同的反馈可用性和标注量假设。
  • 指标强调不同目标：Pass@1 加多检查点完成、成本-准确率、UQ 排名迁移与共形半径或 VideoQA 准确率，导致跨基准比较脆弱。

开放问题

  • 已报告提升中多少来自骨干模型，多少来自执行框架、技能库、任务生成分布或观察输入？
  • OSWorld、ScienceBoard、WindowsAgentArena 与各基准任务上的增益能否迁移到动态屏幕、拖拽或跨平台界面？
  • 代理应如何学习或显式控制观察频率，以避免界面变化中的过度观察和观察不足？
  • 弱监督与可验证强化学习方法能否在已报告套件之外扩展，而不引入隐藏标注、污染或评测过拟合？
  • 鉴于后验不确定性排名跨模型和跨界面迁移弱，部署中需要哪些不确定性或校准证据？

theory

Formal analysis, task abstractions, interaction theory, or reliability/safety framing for GUI agents

60 方法质量 100 近期性 39 可复现性 42 主题相关性

文献综述归纳

研究路线

任务表面形式化与基准构建

把桌面工作流、拖拽交互、动态内容流和单步定位等GUI能力转化为可复现任务，并引入确定性或成本感知指标。

尚未覆盖：这些任务特定形式化与评分规则是否跨界面和多步轨迹迁移尚不清楚；若干记录缺少局限与工件细节。
面向冻结代理的证据驱动可靠性层

通过外部技能库、执行框架编辑或不确定性估计，以截图、重复运行和执行前后状态为证据改进冻结模型。

尚未覆盖：跨模型和跨接口的可靠性信号迁移较弱；分布偏移下覆盖率下降，动态界面中的观察控制仍缺失。
GUI控制的可扩展监督与在线训练

利用未标注截图、可验证合成任务、前沿采样和多模态技能工件降低标注成本或提高训练效率。

尚未覆盖：弱监督或合成监督的收益是否代表稳健泛化还是基准特定过拟合仍有验证缺口；安全与可验证性边界不明确。

研究共性

  • 细粒度或成本感知评测能揭示Pass@1无法反映的子目标完成度与观察效率差异。
  • 截图、视觉图形、执行前后状态和重复运行等外部证据可在不修改骨干权重的情况下改进诊断或性能。
  • 当前代理在动态界面、跨类/跨接口迁移和分布偏移下仍不够可靠；观察控制与置信度校准较弱。
  • 任务特定形式化对可复现性很重要，但通常绑定特定界面或评测机制。

关键差异

  • 改进位置：训练时RL或弱监督，与冻结模型外部技能库/执行框架优化形成不同路线。
  • 评测目标：静态多应用桌面任务、纯拖拽交互、动态信息流以及单步GUI定位不确定性强调不同失败模式。
  • 监督/验证信号：确定性规则评分、成本准确率的信息效率以及共形置信覆盖隐含不同的正确性假设。
  • 技能表示：视觉+文本工件在匹配条件下优于纯文本技能，但证据范围仍有限。

开放问题

  • 基准形式化在原始界面之外，尤其是多步轨迹和未知平台上的可迁移性如何？
  • 后验不确定性估计能否在开放权重与闭源模型以及不同接口之间迁移，而不需要目标特定重排序？
  • 动态界面中的观察控制是否需要显式架构或执行框架设计，还是可以通过训练扩展与外部记忆产生？
  • 弱监督与可验证合成任务的收益在分布偏移、长程任务和安全关键GUI工作流中是否稳健？
  • 证据包中若干论文缺少代码、数据集、基线或局限性细节，构成尚待核验的可复现性缺口。

system

59 方法质量 99 近期性 40 可复现性 43 主题相关性

研究路线

端到端原生计算机使用策略

将视觉定位、GUI操作和代码执行统一为跨桌面、网页和移动任务的多模态控制问题。

尚未覆盖：跨平台泛化与恢复行为；部分工作未提供明确局限性，独立复现证据不足。
数据高效的GUI智能体学习

通过未标注截图预训练、课程校准或可验证合成任务，减少对昂贵人工标注的依赖。

尚未覆盖：弱监督与合成监督在跨应用、跨语言和长流程任务中的可扩展性尚不明确。
快速潜空间动作评分

通过在联合嵌入潜空间中评分候选动作，而非逐token解码动作文本，满足移动端延迟和参数约束。

尚未覆盖：报告准确率仅达到微调VLM基线的86–92%，且评估主要覆盖 AndroidControl。
可复用多模态技能与工具库

通过分层技能工件和 MCP 风格工具，为智能体提供按需的过程性知识和视觉图形。

尚未覆盖：技能构建成本、跨应用可移植性，以及 UI 变化后视觉工件是否仍然可靠。

研究共性

  • 近期工作趋向于将 GUI 控制与代码或工具执行统一，而不是把点击和命令当作独立动作。
  • 普遍尝试用弱监督、合成、混合或强化学习采集的监督替代昂贵的人工标注。
  • 评测越来越行为和诊断化，除基准成功率外还探测错误恢复、个性化时机和动作结果一致性。
  • 延迟、Harness 兼容性和可复现性等部署相关约束开始受到更多关注。

关键差异

  • 策略形式不同：完整多模态生成、块级扩散生成和无解码器潜评分在速度与准确率之间做出不同取舍。
  • 监督设置不同：未标注截图加强化校准、合成应用工件与可验证结果、以及真实 Harness 回放训练分别具有不同的覆盖与复现假设。
  • 评测重点不同：总体成功、恢复一致性、偏好遵循的阶段探针和吞吐量衡量了不同的失效模式。
  • 部分预训练组件的价值存在争议；一项结果表明预测器的屏幕动态预训练并未优于随机初始化。

开放问题

  • 低延迟潜空间策略能否在保持参数优势与速度优势的同时，缩小与完整 VLM 智能体之间的准确率差距？
  • 当重放和重置昂贵或不可用时，哪种监督策略最能改善 Harness 训练智能体的错误恢复？
  • 分层技能库如何在不同应用和持续 UI 变化中迁移，而无需人工重建？
  • 哪种行为诊断最能预测实际部署可靠性：恢复一致性、偏好时机还是静态任务成功率？
  • 当前复现信号是否足够？鉴于若干证据条目缺少局限性细节，缺失负面结果是验证缺口。

application

Domain applications of GUI agents, such as office automation, mobile apps, web tasks, software operation, or professional tools

63 方法质量 99 近期性 39 可复现性 45 主题相关性

文献综述归纳

研究路线

面向GUI智能体的真实应用基准与任务覆盖

为桌面、动态短视频、拖拽式交互和视频引导任务提供细粒度、基于规则或保真度感知的评测。

尚未覆盖：覆盖范围受平台或交互类型限制；动态界面下智能体未达到人类水平成本-准确性，观察控制仍不足。
面向重复计算机使用任务的可复用技能、记忆与重放策略

将成功运行或分层多模态技能编译为可复用程序，使智能体减少每步语言模型调用并提升效率。

尚未覆盖：UI或工作流变化时的泛化、存储程序的干净状态验证，以及检索鲁棒性仍缺乏充分测试。
从真实应用或网页自动重建环境与数据集

从真实URL自动重建源对齐的、可复用的网页/应用环境或大规模交互数据集，减少站点级人工实现。

尚未覆盖：仍需每站点初始授权；重建保真度向真实下游任务成功的迁移证据有限。
多模态GUI智能体架构与交互定位

构建或微调视觉语言代理，以改善跨平台GUI定位和导航，包括拖拽交互和块级扩散生成。

尚未覆盖：开源权重复现、跨平台迁移，以及架构收益在已报告基准之外的持续性仍不明确。

研究共性

  • 评测正从二元成功转向细粒度多条件完成，例如子目标检查点、成本-准确性、保真度和交互类型覆盖。
  • 可复用工件，包括多模态技能、重放程序或重建环境，能在不依赖模型规模的情况下提升效率或下游表现。
  • 视觉图形、屏幕状态检查和关键帧对UI元素识别、工作流验证和动态观察控制具有重要作用。
  • 许多基准和方法论文存在验证缺口：代码、数据、指标或局限披露不完整。

关键差异

  • 表示与生成方式不同：文本技能、多模态视觉工件、块级扩散视觉语言代理、任务驱动关键帧提取。
  • 监督与改进信号不同：规则评分、交互数据微调、技能库检索、带状态机回退的重放、环境重建验证。
  • 评测目标与交互模式不同：静态桌面/网页点击输入、GUI+CLI混合、拖拽手势、动态短视频流、视频引导任务。
  • 部署假设不同：有些需要每站点授权，有些假设干净状态验证，有些依赖运行时屏幕检查、护栏或检索器选择。

开放问题

  • 在应用特定基准上测得的提升能否迁移到未见过的桌面、移动、网页或专业工具工作流？
  • 需要怎样的观察控制机制来缩小当前代理与人类水平成本-准确性之间的差距？
  • 存储技能和重放程序在UI漂移或工作流变化下如何表现，哪些验证与回退条件足够？
  • 鉴于许多高排名论文未完整提供代码、数据、指标或局限，最少需要哪些可复现工件？
  • 块级扩散或多模态技能的收益在更广泛应用集合和开源基线评估下是否仍成立？

为视频引导GUI任务、桌面定位、移动长程任务和短信到网页欺诈检测建立受控设置，并给出任务完成或定位指标。

通过可验证任务合成、在线RL、密集桌面标注或证据驱动的harness编辑，提升冻结或开放的GUI智能体在OSWorld、ScienceBoard等套件上的表现。

研究共性

  • GUI智能体工作通常在冻结或微调的MLLM/VLM骨干之上添加外部机制，而非替换骨干。
  • 进展主要通过特定基准上的任务完成率或定位准确率衡量，并常附带留出集或分布外迁移声明。
  • 评测协议趋向受控化，包括净化证据、隐藏捷径或标准化环境交互。
  • 数据、代码或逐项记录的公开被视为重要，但报告程度不一。

关键差异

  • 监督信号从基于可验证任务的在线RL，到密集标注的监督微调，再到冻结模型harness优化各不相同。
  • 策略表示分为解码文本动作和在联合嵌入潜空间中对候选动作评分两种。
  • 评测目标不同：单步GUI定位、长程任务完成、视频引导交互，以及隐藏信誉线索下的欺诈判断。
  • 部署设置跨移动、桌面、网页与短信到网页，以及闭源与开放权重模型存在差异，界面假设不同。
