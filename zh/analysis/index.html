benchmark

GUI/web/mobile/OS automation datasets, environments, tasks, metrics, and benchmarks

62 方法质量 99 近期性 39 可复现性 45 主题相关性

文献综述归纳

研究路线

真实桌面与 OS 任务套件设计

在跨应用、GUI 与 CLI 混合的真实 macOS 任务中提供确定性检查和细粒度子目标评分，使部分完成和能力差异可比较。

尚未覆盖：跨移动、网页和动态流式界面迁移证据不足；规则评分能否在非桌面 UI 上普适仍未知。
动态与视频引导界面任务套件设计

刻画内容在操作间变化的短视频平台界面及视频引导任务，评估观察控制、信息效率和任务相关关键帧使用。

尚未覆盖：平台覆盖较窄；模型未达到人类水平成本-准确性，观察控制缺陷仍未解决。
不确定性与校准压力测试

在 GUI grounding 上跨开源/闭源模型和数据集评估事后不确定性方法，测量排序迁移和共形点击区域覆盖。

尚未覆盖：仅覆盖单步 grounding；跨层级排序迁移弱，分布/接口偏移下覆盖度下降，多步部署未验证。
共享 GUI 基准上的干预与训练评测

在 OSWorld-Verified、CUA-World、OSExpert-Eval、ScienceBoard 等共享基准上评估技能库、harness 优化、弱监督、在线强化学习等干预是否改善代理。

尚未覆盖：收益是否来自通用能力或对特定 benchmark/harness 的过拟合不确定；迁移证据有限，算力与数据预算不可比，部分高排名结果缺少 explicit limitations。

研究共性

  • 当前计算机使用评测偏向真实交互环境而非静态截图，常使用多步任务和基于规则或可执行的检查。
  • 单一总成功率不够；需要子目标、成本效率或不确定性等细粒度指标区分总分数接近的模型。
  • 前沿视觉语言代理仍存在系统差距：动态界面中的观察控制不足、跨模型层级的不确定性排序迁移弱、与人类水平成本-准确性差距大。
  • 共享测试集如 OSWorld、OSWorld-Verified、CUA-World、OSExpert-Eval、ScienceBoard 被广泛使用，便于比较冻结模型与不同干预策略。

关键差异

  • 任务设置：静态桌面/OS 工作流与动态 living-screen 或视频引导界面不同，后者内容在操作间变化。
  • 评测目标：多步任务完成与单步 GUI grounding 不确定性不同，跨评测目标的结论不可直接迁移。
  • 主要改进轴：冻结模型的技能/harness 优化与基于训练的弱监督或在线强化学习不同，报告提升可能反映不同机制。
  • 成功标准：基于规则的 pass-rate 与成本准确性和信息效率指标不同。
  • 接口访问：开源权重模型可访问隐藏状态，闭源供应商不可访问，导致不确定性评测不对称。

开放问题

  • 如何在不牺牲确定性或可验证评分的前提下，扩展基准到跨平台和动态界面变化？
  • 能否将单步 GUI grounding 的不确定性和校准指标扩展到多步轨迹，同时避免覆盖度下降？
  • 技能、harness 和训练带来的提升在不同实现、算力预算和未见过基准上是否稳定？
  • 需要哪些观察控制机制才能使动态屏幕代理接近人类水平的成本-准确性？
  • 当前高排名工作普遍缺少明确的 limitations 或可复现细节，如何审计其结论稳健性？

method

GUI agent models, planning, grounding, action prediction, training, or reasoning methods

62 方法质量 99 近期性 38 可复现性 45 主题相关性

文献综述归纳

研究路线

方法表示与目标设计

把GUI智能体训练落实为弱监督、强化学习和可验证任务合成目标，减少标注或扩大验证覆盖。

尚未覆盖：这些目标是否迁移到OSWorld、ScienceBoard和UI-TARS式对比之外，以及未标注截图学习到的视觉定位是否支撑长程执行。
规划与动作接口方法

通过优化执行框架、观察行为、关键帧选择和拖拽等交互模式，把模型输出连接为可执行动作。

尚未覆盖：模型增益有多少来自模型本身，而不是规划器、执行框架或接口实现，以及这些选择在未知任务上的迁移性。
可验证任务合成与在线强化学习扩展

生成可验证计算机使用任务并分配在线采样，以提高GUI智能体的样本效率。

尚未覆盖：评测集中于OSWorld和ScienceBoard；跨环境验证与长尾界面变化的覆盖仍不明确。
方法证据与消融协议

通过细粒度评分、子目标指标、不确定性基准和专项数据集，区分方法贡献与数据集/基准因素。

尚未覆盖：证据大多集中在单一基准或单一接口；多步轨迹和分布偏移鲁棒性尚未被隔离验证。

研究共性

  • GUI方法工作正把建模改进与可执行或可验证的计算机使用任务绑定，常在OSWorld、ScienceBoard或桌面/网页/视频等评测环境上验证。
  • 子目标完成、成本-准确性、观察行为、拖拽正确性和不确定性校准等细粒度信号能揭示Pass@1掩盖的缺口。
  • 训练与自改进方法通过未标注截图、可验证合成任务或重复运行证据，减少对昂贵密集标注的依赖。
  • 界面假设成为方法设计的核心；动态内容、GUI/CLI混合和拖拽动作会影响定位质量与任务执行。

关键差异

  • 监督信号不同：基于大规模未标注截图的视觉定位、基于可验证任务的在线强化学习，以及保持骨干冻结只优化执行框架。
  • 评测目标不同：总体成功率、子目标完成、成本-准确性、不确定性/覆盖率并非同一指标，会得到不同结论。
  • 交互覆盖不同：单步可执行定位、多步应用任务、拖拽交互和动态短视频界面的覆盖不均衡。
  • 迁移证据不同：冻结执行框架展示出跨基准迁移，但不确定性排名跨模型/接口迁移弱，训练增益多集中在特定基准。

开放问题

  • 报告增益能否分解为模型、执行框架/规划器、技能库、基准选择和数据配方的贡献？
  • 不确定性量化与观察控制结论能否从单步定位和短视频场景扩展到多步桌面代理轨迹？
  • 可验证合成任务和未标注截图目标是否覆盖足够的长尾界面变化以支持部署？
  • 关于拖拽、动态内容和跨应用GUI/CLI交互的方法评测证据还有哪些缺口？

theory

Formal analysis, task abstractions, interaction theory, or reliability/safety framing for GUI agents

62 方法质量 100 近期性 38 可复现性 45 主题相关性

文献综述归纳

研究路线

面向评测的任务与交互抽象

通过建模动态内容、拖拽原语、细粒度子目标与观察成本，揭示聚合成功率无法反映的代理能力差异。

尚未覆盖：抽象与平台和套件绑定，缺少证据表明所选任务分解覆盖完整交互空间或能在部署环境间迁移。
基于证据的技能与harness自适应

利用操作前后截图和重复执行进行诊断，在冻结模型外部修改技能或harness以提升GUI表现。

尚未覆盖：迁移验证仅限少数基准，且依赖源码级harness变更；未被编辑模式覆盖的失败仍缺乏验证。
弱监督与在线强化学习策略训练

利用未标注截图、可验证任务合成和在线RL降低标注成本与采样低效问题。

尚未覆盖：证据主要集中在任务成功与训练速度，分布偏移下的可靠性、安全性与失败模式尚不明确。
不确定性量化与可靠性框架

评估GUI grounding的后验置信度与空间校准，将模型输出连接到风险感知的点击区域。

尚未覆盖：当前评测限于单步grounding，UQ排序跨模型类别和接口迁移较弱。

研究共性

  • 可验证或细粒度评测信号正取代粗粒度任务成功，因为它们揭示聚合通过率掩盖的能力差异。
  • 视觉与执行证据，包括截图和重复运行，有助于定位UI理解与工作流验证中的失败。
  • 当前GUI代理在动态场景、观察控制、拖拽交互和校准置信度方面仍存在明显可靠性缺口。
  • 冻结模型适配和数据高效训练可以提升性能，但泛化与安全证据仍然较窄。

关键差异

  • 评测目标不同：真实桌面多应用完成、动态短视频交互、拖拽动作或单步grounding校准。
  • 适配层次不同：修改多模态技能工件、优化可执行harness、在合成任务上微调或RL，或从无标注截图学习。
  • 监督与目标不同：确定性规则评测、成本-精度优化、可验证RL奖励、弱视觉监督或后验不确定性校准。
  • 可靠性处理不同：有的以观察成本刻画部署风险，有的以空间点击不确定性刻画；缺少统一安全度量。

开放问题

  • 细粒度基准指标能否预测真实环境中的GUI代理可靠性与失败恢复能力？
  • UQ排序能否在不重新校准的情况下跨模型类别和可观察接口稳健迁移？
  • 面对动态界面，何种观察控制策略能避免过度观察或观察不足？
  • 拖拽、动态内容和多应用抽象是否足以覆盖完整GUI动作空间与失败模式？
  • 技能/harness和弱监督带来的提升能否在特定基准环境之外持续成立？

system

Runnable GUI agent systems, frameworks, sandboxes, tool-use platforms, or orchestration layers

60 方法质量 99 近期性 38 可复现性 45 主题相关性

文献综述归纳

研究路线

可运行的端到端智能体训练与部署栈

将 GUI、网页和 harness 环境转化为闭环训练工作流，利用少量精选或弱标注数据，减少人工标注并接入标准 RL 代码库。

尚未覆盖：训练后错误恢复仍弱，且不同 harness 设计显著影响可训练性；超出已验证基准和环境的泛化能力尚未建立。
可复用技能与记忆编排层

记录经过验证的 GUI 轨迹或多模态技能工件，使智能体可召回参数化流程，在改善 grounding 的同时降低 token 成本与执行时间。

尚未覆盖：复用依赖确定性运行状态检查，并会拒绝模糊或不兼容步骤；对新的应用状态和实时 UI 漂移的适应仍有限。
高效多模态 GUI 智能体建模与训练范式

通过未标注截图弱监督或块级扩散解码开发视觉语言 GUI 智能体，减少标注数据需求或保持并行解码优势。

尚未覆盖：速度、控制保真度和实时交互之间的权衡尚未充分探索；报告增益受限于特定 grounding/导航基准。
诊断性与领域专用评测环境

构建基于执行的基准，隔离 GUI 状态转换理解或专家科学软件工作流，超越仅看最终任务成功。

尚未覆盖：离线诊断无法捕获实时异步时序和延迟；当前任务集受限于特定操作系统、动作集或专家领域。

研究共性

  • 基于执行的评测正在取代单帧 grounding 或仅最终准确率，成为 GUI 智能体进展的核心证据。
  • 结构化可复用工件（技能、可调用记忆或轨迹）无需重新训练模型即可显著降低 token 成本或执行时间。
  • 训练框架趋向于将智能体模型与 harness、环境解耦，以便在真实或实时 GUI 设置中应用强化学习或弱监督。
  • 模型在状态验证、转换理解和错误恢复方面仍明显落后于专家工作流。
  • 开放基础设施和工件信号不均衡，使独立复现存在验证缺口。

关键差异

  • 训练信号不同：未标注截图弱监督、在线多轮强化学习，以及经 harness 的端到端 RL。
  • 复用表示不同：多模态技能库保留视觉图形，而可调用执行记忆按确定性和参数化步骤运行，并拒绝无法安全重放的轨迹。
  • 评测目标不同：离线步骤级转换诊断、实时网页任务成功，以及专家科学软件任务。
  • 建模范式不同：块级扩散解码与传统视觉语言模型驱动的 harness 式计算机使用智能体。
  • 部署方式不同：训练期策略优化与推理期记忆/技能复用，并覆盖 Linux 桌面、网页和专用科学软件等不同场景。

开放问题

  • 错误恢复如何在强化学习后仍较弱的情况下被显式训练或通过脚手架补偿？
  • 多模态技能和可执行记忆能否在异步 GUI 时序、跨应用和跨操作系统 UI 变化下持续泛化？
  • 扩散式 GUI 智能体在实时服务中的延迟与交互保真度权衡是什么？
  • 弱监督和在线 RL 的成果能否迁移到超出当前报告的桌面、网页和科学软件任务之外？
  • 实时任务成功、状态转换诊断和专家产物检查中，哪类评测最能预测真实部署可靠性？

application

Domain applications of GUI agents, such as office automation, mobile apps, web tasks, software operation, or professional tools

65 方法质量 99 近期性 37 可复现性 49 主题相关性

文献综述归纳

研究路线

面向应用的GUI基准与任务套件

衡量多步骤真实计算机操作能力，覆盖桌面、动态短视频、拖拽和视频引导交互，并提供细粒度成功率与成本指标。

尚未覆盖：覆盖仍限于所选平台与交互类型；动态界面智能体在成本-准确性上仍低于人类，尤其观察控制不足。
可复用的多模态技能与执行记忆

将验证过的智能体轨迹转化为分层视觉/文本技能或可重放程序/记忆，降低token成本与执行时间，保持重复任务成功率。

尚未覆盖：重放与技能检索依赖确定性屏幕/前置条件匹配；界面变化、模糊步骤和跨应用泛化证据仍不足。
GUI智能体模型架构与任务特定适配

通过扩散视觉语言建模或针对拖拽等专门交互数据的微调，提高移动、桌面和网页平台的视觉定位与动作生成能力。

尚未覆盖：评测集中在选定基准上；真实应用、跨任务迁移和分布漂移下的稳健性尚未建立。
多模态观察与视频/关键帧证据

从动态屏幕或视频中提取任务相关视觉证据，以支持GUI智能体决策和视频引导的交互任务。

尚未覆盖：现有智能体存在过度观察或观察不足；关键帧/观察策略在特定基准上有效，但缺乏更广泛GUI应用的证据。

研究共性

  • 端到端GUI智能体表现多以应用级、多步骤任务评估，而非孤立的UI元素识别。
  • 视觉定位与状态验证被视为核心瓶颈，通过视觉技能工件、屏幕检查或关键帧提取来处理。
  • 将已验证工作流复用为技能、程序或记忆，是减少重复语言模型调用与执行成本的新兴方向。
  • 需要比Pass@1更细粒度的指标，因为相近任务成功率可能掩盖子目标、成本或信息效率差异。

关键差异

  • 评测环境动态性不同：静态或准静态桌面/移动任务与界面内容在操作间变化的短视频任务并存。
  • 贡献层次不同：有的构建基准或数据集，有的改进模型架构或微调策略，有的增加事后重放/技能层。
  • 成功标准不同：有的报告Pass@1或子目标完成度，有的采用成本-准确性或信息效率，有的报告token与时间减少。
  • 交互范围不同：从点击/输入到拖拽操作、GUI+CLI控制以及视频引导任务完成均存在差异。

开放问题

  • 编译后的技能、程序或记忆在应用更新、布局变化和未见多应用工作流中的迁移能力如何，仍需证据。
  • 在持续变化界面中，何种观察控制机制能在足够视觉证据与token/时间成本之间取得平衡？
  • 除Pass@1外，子目标完成度、成本-准确性、运行效率等维度中哪些最能预测真实计算机操作的可靠性与用户价值？
  • 拖拽或视频引导等专门交互基准是否提升通用GUI智能体能力，还是仅改善窄分布表现？

  • 受控任务设计与基于基准的评测是衡量GUI智能体进展的核心方式。
  • 冻结或开放权重视觉语言骨干可通过外部监督、harness修改、上下文管理或生成任务得到提升。
  • 单步或单任务成功率提升不会自动迁移到不同基准、领域或模型层级。
  • 安全性、不确定性和泛化被作为独立评测面处理，迁移证据通常较弱或缺失。

关键差异

  • 介入层级不同：部分工作修改训练任务或在线强化学习，部分编辑执行harness、管理上下文或校准后验不确定性。
  • 监督信号不同：可验证强化学习任务、密集桌面标注、关键帧提取和人工整理欺诈或安全案例带来不同覆盖偏差。
  • 评测设置不同：单步可执行定位、长程移动或桌面任务完成、对抗与净化证据场景各有不同。
  • 部署假设不同：部分依赖内部状态进行隐藏状态不确定性估计，部分仅面对闭源供应商或冻结模型，可观测性有限。
