StateAct：程序状态优先于像素，用于长时程计算机使用代理

arXiv 2026 57.5 method, system

TLDR

StateAct通过程序状态（代码）而非像素驱动计算机代理，仅在必要时使用GUI子智能体，实现更高成功率和更低成本。

评分理由

The paper introduces a novel code-first multi-agent framework that leverages program state over screenshots, supported by empirical results on OSWorld 2.0 showing improved performance and efficiency. A weakness is that the approach may not generalize to all UI scenarios, and the reliance on code access limits applicability.

深度分析

创新点

  • 代码优先的多智能体框架，直接操作程序状态（状态立足），而非仅依赖截图感知。
  • 专用的GUI子智能体仅在必要时（1.1%的步骤）调用进行像素交互，保持主智能体以代码为中心。
  • 独立的完成门，验证保存结果的结构性失败（缺失、未保存或路径错误的输出）。
  • 通过为子目标创建新的子智能体来管理上下文，使主智能体在长时程中保持聚焦。
  • 状态立足的概念：将动作、验证和记忆立足于程序状态而非像素渲染。

方法

StateAct是一个多智能体系统，主智能体通过代码操作程序状态，GUI子智能体仅在需要时处理截图-点击任务。独立的验证完成门检查输出是否存在结构性错误。该系统在OSWorld 2.0基准上使用Claude Opus 4.8进行评估，比较了完整StateAct、无GUI子智能体的纯代码变体以及纯截图基线。

关键结果

在OSWorld 2.0上，StateAct将Claude Opus 4.8的二元成功率从20.6%提升至26.9%，部分成功率从54.8%提升至61.6%，每个任务的成本约为纯截图基线的1/9。无GUI子智能体的纯代码变体仅达到45.9%的部分成功率，低于截图基线的54.8%。

局限性

  • 失败从感知转向推理：主要瓶颈成为代理的想法而非其看到的内容。
  • 纯代码方法在部分成功率上低于截图基线（45.9% vs 54.8%），表明某些任务本质上需要GUI交互。
  • GUI子智能体在108个任务中仍有28个需要，因此系统并非完全纯代码。
